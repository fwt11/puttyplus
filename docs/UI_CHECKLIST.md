# 新界面开工前的检查清单（UI 审查 2026-11-18 的沉淀）

> **为什么有这份东西**：`docs/UI_AUDIT.md`（2026-10-18 全局审查）里 §7 的
> P0 已经落地，但**容器工作台（v0.9.0，2026-11-18 审查）又犯了一遍**
> —— 监控曲线把颜色写死（`set_source_rgb(1.0, 1.0, 1.0)`）⇒ 暗色主题下
> 是四个白盒子。⇒ 说明审查结论**没有沉淀成「开工前要过的检查清单」**
> ⇒ 补上这一份。
>
> **用法**：**新界面 / 新控件开工前**逐条过一遍；做完在下面签字。
> 每条都给了「怎么验」——**没验过的不算做完**。

## 0. 颜色与主题（最常犯 ⇒ 排第一）

| # | 检查项 | 怎么验 |
|---|---|---|
| 0.1 | **不许写死颜色常量**（`set_source_rgb(1.0, 1.0, 1.0)` / `#ff0000` / `Color::from_rgb`）⇒ 一律走 `theme::state_hex` / `theme::fg_hex` / `theme::dim_hex` / `theme::panel_hex` | `grep -n "set_source_rgb\|from_rgb\|#\(ff\|00\)" 你的新文件` ⇒ 只有「主题表」里能出现 |
| 0.2 | **cairo 自绘的控件（`DrawingArea`）不过 CSS** ⇒ 颜色**必须自己从主题令牌取**，而且**每次重画都重新取**（切主题才跟着变） | 切到暗色主题 ⇒ 画的东西还是暗色的 |
| 0.3 | 语义色（绿/黄/红）用 `theme::State`（`Ok` / `Warn` / `Err`）⇒ 主题自带**高对比**那一套 | 主题切到「高对比」⇒ 状态点仍分得清 |
| 0.4 | 次要文字用 `dim-label` / `theme::dim_hex()`（**不是**系统的 `insensitive_fg_color` ⇒ 那个在浅色下只有 3.03:1） | 浅色主题下量对比度 ≥ 4.5:1 |

## 1. 文字与文案

| # | 检查项 | 怎么验 |
|---|---|---|
| 1.1 | **用户可见文案全中文** ⇒ 远端返回的原文（docker 的 `Up 13 hours`、ls 的权限串）**要翻** | 界面上搜不到英文残句 |
| 1.2 | 走 `tr()` / `trf!` ⇒ **英文界面才有译文** ⇒ 新文案要补进 `src/i18n_en.rs` | `cargo test --lib i18n::` ⇒ 绿 |
| 1.3 | **占位符两边要对得上**（`{n}` 在译文里也要有 `{n}`） | `cargo test --lib i18n::` ⇒ 绿 |
| 1.4 | 长文字要 `set_wrap(true)` **且**限宽（`set_max_width_chars`）⇒ 不然自然宽把容器撑破 | 窄面板里不裁 |
| 1.5 | ⚠️ **`trf!` 只认 `{名字}`** ⇒ 带格式说明的占位符（`{v:.1}`）**不会被替换** ⇒ 数字先用 `format!` 打好再拼 | 界面上搜不到 `{` `}` 残留 |

## 2. 布局与密度

| # | 检查项 | 怎么验 |
|---|---|---|
| 2.1 | 表格列**给下限宽度** ⇒ 不然长文本把关键列挤成「s…」 | 每列都有 `set_min_width` |
| 2.2 | 内容多的地方**能滚** ⇒ 详情区高度是「窗口高 − 写死的数」⇒ 窗口一矮就看不见 | 把窗口缩到**主窗默认尺寸**（1200×780）再看 |
| 2.3 | 工具条**别塞十几个控件** ⇒ 拆成「筛选组 | 操作组」，窄窗口时压扁的是可伸缩的那个 | 窗口拉窄 ⇒ 操作按钮**不被挤出去** |
| 2.4 | 同一屏**只留一个**同义控件（两个刷新按钮 = 用户不知道点哪个） | 界面上找重复动作 |
| 2.5 | 卡片/网格的**行高自适应** ⇒ 文字多的那格不能压掉旁边那格 | 内容塞满看有没有互相裁 |

## 3. 空态与错态

| # | 检查项 | 怎么验 |
|---|---|---|
| 3.1 | 空列表 / 出错**不许只留一块空白** ⇒ 用 `emptystate::build`（标题 + 解释 + 主 CTA） | 断网 / 连不上时看列表区 |
| 3.2 | **不同的错要给不同的标题**（没装 docker / 没权限 / 服务没起）⇒ 不能长得一模一样 | 制造三种错各看一眼 |
| 3.3 | 空态有**真动作可点**（「重试」）⇒ 没有动作就别硬塞（见 `dbui.rs` 的反例） | 点 CTA 有反应 |
| 3.4 | 「正在加载」的动画**与空态不同时出现** | 刷新时看一眼 |

## 4. 状态与数字

| # | 检查项 | 怎么验 |
|---|---|---|
| 4.1 | 状态行说**当前的**事 ⇒ 过滤/切换后数字要对（`显示 1 / 共 2` 而不是 `共 2`） | 过滤一下看底栏 |
| 4.2 | 每个分段/子页**各有自己的状态** ⇒ 上一段的状态不许污染下一段 | 切页看底栏 |
| 4.3 | **同一个量只用一种单位**（表格给绝对值、卡片给百分比 ⇒ 用户没法对照） | 两个界面各看一眼 |
| 4.4 | ⚠️ **同一列里也一样**：父行（compose 摘要）与子行的单位、小数位要一致 ⇒ 父行「59.3 MB」vs 子行「59.3MiB」会让人以为是两个量 | 展开一个 compose 项目，看父行与子行 |

## 5. 可发现性与键盘

| # | 检查项 | 怎么验 |
|---|---|---|
| 5.1 | **隐藏交互要有提示**（双击进 shell ⇒ 界面上写一行字） | 新用户不用猜 |
| 5.2 | 表格能**排序** ⇒ 点列头 ⇒ **按数值**排（`"9.5%"` 不能排在 `"50.8%"` 前面） | 排序后看顺序对不对 |
| 5.3 | 有**右键菜单**（写操作不该只能「选中 → 滚到下半区 → 点按钮」） | 右键一行 |
| 5.4 | 有**键盘**（↑↓ 选行 / Enter 主操作 / `/` 搜） | 键盘走一遍 |
| 5.5 | **灰掉的按钮要说明为什么不能点**（tooltip）⇒ 别让用户猜 | 悬停灰按钮 |

## 6. 弹窗与层级

| # | 检查项 | 怎么验 |
|---|---|---|
| 6.1 | 弹窗**有 transient parent** ⇒ 否则可能落在主窗**后面** | 实机日志里没有 `GtkDialog mapped without a transient parent` |
| 6.2 | 同一类内容**住在同一个地方**（编辑器搬进页面了 ⇒ 终端也该在页面里） | 找一找有没有另一个窗口 |
| 6.3 | 写操作**二次确认**，且默认焦点在「取消」 | 手快按回车不会误操作 |

## 7. 性能

| # | 检查项 | 怎么验 |
|---|---|---|
| 7.1 | **别整表重画**（项目踩过「整表重画把主线程拖死」）⇒ 只标脏要改的那几行 | 数**单元格实际绘制次数**（不是数自己调了几次 `queue_draw`） |
| 7.2 | 动画/进度**限流**（60ms 一帧 ⇒ 100ms 一次的进度） | 传输时界面不卡 |
| 7.3 | 表格**模型与光标**在刷新后要保住（用户刚点开的容器不能被刷新顶掉） | 选中 → 等自动刷新 → 还在 |

## 8. 设计令牌 v2（美化·地基批 2026-11-19 起的原语，新界面优先用这些）

> **原语长什么样**：`xvfb-run -a cargo run --example design_gallery`
> ⇒ 明暗各截一张（`/tmp/pp-gallery-light.png` / `-dark.png`），
> 那个窗口就是整套原语的活画廊——**选型先看图**。

| # | 检查项 | 怎么验 |
|---|---|---|
| 8.1 | **卡片**用 `.pp-card`（圆角 10 + 1px 边框 + 卡片面 + 内边距 10/12）⇒ 别再各写一套圆角边框 | 暗色下看得出「窗底 < 面板 < 卡片」三层 |
| 8.2 | **状态**用 `.pp-pill` + `-ok/-warn/-err/-dim`（widget）或 `pillcell::PillCellRenderer`（表格列）⇒ 别再用「● 文字」裸 markup 起新状态位 | 画廊里四档药丸一眼分得清 |
| 8.3 | **快捷键提示**用 `.pp-kbd`（键帽）⇒ 别写「按 Ctrl+F」裸文字 | 键帽有底有边框 |
| 8.4 | **技术值**（ID / 端口 / 路径 / 哈希）用 `.pp-mono` 或 renderer `set_family("monospace")` ⇒ 比例字体数错位 | 截图里字母对齐 |
| 8.5 | **数字列右对齐**（`CellRendererExt::set_alignment(&r, 1.0, 0.5)` + 列头 `col.set_alignment(1.0)`） | 数量级竖着对齐 |
| 8.6 | **cairo 自绘的图/卡**底板画圆角（`dockerui.rs::rounded_rect_path` 那套）+ 颜色全走令牌 | 暗色下不是直角白盒子 |
| 8.7 | **弹层不碰阴影/透明**（X11 弹层不透明 ⇒ box-shadow 画成黑块）；阴影只用普通容器 | 弹层四角没有黑角 |

## 9. 表面层级、间距尺度与控件节奏（阶段 175 / UI-08，治 P2-2）

> **为什么单开一节**：审核 P2-2 说「单页好看，放在一起却像不同时期拼起来」
> —— 根因不是某一页难看，而是**没有共同的尺子**。
> ⇒ 这一节就是那把尺子：**表面有固定的四层、间距只有五档、控件高度统一**。

### 9.1 表面层级（四个面，**不许省掉中间层**）

| 层 | 令牌 | 用在哪 | 规则 |
|---|---|---|---|
| 窗口底 | `pp_bg` | 窗口背景、工具窗背景 | 最外层 |
| 面板面 | `pp_panel` | 侧栏、对象树、SQL 编辑器、结果网格 | 比窗底**亮/暗一层** |
| 卡片面 | `pp_card` | 需要**独立边界**的容器（`.pp-card`） | 比面板面**再分一层** |
| 输入面 | `pp_input` | `entry` / `spinbutton` | 与面板面分开 ⇒ 一眼看出「这里能打字」 |
| 选中面 | `pp_selected` | 选中行（`list > row:selected` / `treeview.view:selected`） | 与 hover 分得开 |

| # | 检查项 | 怎么验 |
|---|---|---|
| 9.1.1 | **浅色主题也必须三层可辨**（窗底 < 面板 < 卡片）—— 2026-11-27 前浅色是 `bg #f3f4f6 / panel #ffffff / card #ffffff`，**面板与卡片同色** | `cargo test --lib theme::` ⇒ `卡片面比窗底亮一层_暗色三层分得开` 绿 |
| 9.1.2 | 三套主题**令牌齐全**（`pp_bg/pp_panel/pp_card/pp_input/pp_border/pp_hover/pp_selected/pp_accent/pp_accent_soft`） | 同上 ⇒ `三套主题的表面令牌都齐` 绿 |
| 9.1.3 | **输入面 / 选中面真的接在 CSS 上**（加了令牌却没接 ⇒ 等于没加） | 同上 ⇒ `输入面与选中面接到了css上` 绿 |
| 9.1.4 | **高对比主题不靠颜色分层** ⇒ 靠**边框**（`pp_border` 是白的） | 高对比下卡片边界看得见 |
| 9.1.5 | **只给需要独立边界的容器用卡片**（`.pp-card`）⇒ 列表行、表单字段**不普遍卡片化** | 看新页面：一屏里 `.pp-card` 不超过 3 个 |
| 9.1.6 | **弹层不碰阴影/透明**（X11 弹层不透明 ⇒ `box-shadow` 会画成黑块） | 弹层四角没有黑角 |

### 9.2 间距尺度（**只有五档**，代码里用 `theme::space::*`）

| 档 | 值 | 用在哪 | 例 |
|---|---|---|---|
| `XS` | 4px | 同组元素之间 | 图标与文字之间、药丸之间 |
| `S` | 8px | 控件之间 | 按钮之间、表单行之间 |
| `M` | 12px | 小组件之间 | 列表项之间、卡片内的块 |
| `L` | 16px | 区块之间 | 工具栏与内容之间 |
| `XL` | 24px | 页面级留白 | 页面外边距、空态与内容的距离 |

| # | 检查项 | 怎么验 |
|---|---|---|
| 9.2.1 | 新写的间距**只用这五档** ⇒ 代码里用 `theme::space::XS/S/M/L/XL`，别写 `margin_top(7)` | `grep -n "margin_\|padding" 你的新文件` ⇒ 数值都能对上五档 |
| 9.2.2 | **同一屏里不混档**（一块里同时出现 4/7/8/11 ⇒ 看着像拼的） | 看新界面：间距是不是「就那么几档」 |
| 9.2.3 | 紧凑密度（`density.rs` 的 `.pp-compact`）**只压缩不改语义** ⇒ 同一套档位在紧凑下按比例缩小 | 切紧凑模式：层级还在，只是更紧 |

### 9.3 控件节奏

| # | 检查项 | 怎么验 |
|---|---|---|
| 9.3.1 | **图标按钮统一 30×30**（`.pp-icon-btn`：30×30、内边距 2/4） | 一排图标按钮**一样高** |
| 9.3.2 | **表格行高统一**（`treeview.view cell` 的 4px 7px 内边距）⇒ 行高有呼吸感 | 一张表的行**一样高** |
| 9.3.3 | **表单说明文字层级固定**：标题 11pt 粗 / 说明 10.5pt 淡（`pp-hint`）⇒ 别让说明比标题还大 | 看表单 |
| 9.3.4 | **数字列右对齐**（`.pp-mono` + renderer 对齐 1.0） | 数量级竖着对齐 |
| 9.3.5 | **技术值用 `.pp-mono` / `.pp-kbd`**，别用比例字体 | 截图里字母对齐、键帽有底有边框 |

### 9.4 三主题画廊（**改令牌先看图**）

```bash
xvfb-run -a cargo run --example design_gallery
```

⇒ 明 / 暗 / 高对比各截一张（`/tmp/pp-gallery-*.png`）。
**画廊里有「表面层级」那一块**（窗底 / 面板 / 卡片 / 输入 / 选中）⇒
改完令牌先在画廊里确认，别直接改十个页面。
