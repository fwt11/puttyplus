# 跨平台版构建说明（Windows 优先）

> 阶段 C2 起生效。这份文档讲**怎么把 PuTTYPlus 编到 Windows 上**，
> 以及中途需要的额外工具（Zig）。

## 1. 两个终端引擎

| 引擎 | 用在哪 | 依赖 |
|---|---|---|
| **VTE**（libvte 2.91） | Linux（现有主线，行为零变化） | 系统装 `libvte-2.91-dev` |
| **ghostty-vt**（libghostty-vt 1.0） | Windows（新增后端） | **Zig 0.17.x** 现场编译 |

两个引擎都被封在 `src/termview/` 里，应用层只认 `TermView`
（详见 `src/termview/mod.rs` 顶部的说明）。

## 2. 为什么需要 Zig

libghostty-vt 是 **Zig 写的**（Ghostty 官方源码 tarball）。
crates.io 上的绑定 crate（`ghostty-vt` / `ghostty-vt-sys`）都**不带预编译
静态库**，一律在构建时用 Zig 编译 ⇒ **第一次构建要装 Zig 0.17.x**。

Rust 侧用 `ghostty-vt` 0.8.0（安全封装，FFI 细节由
`src/termview/ghostty.rs` 封死）。

## 3. 装 Zig

### Linux（本机）

放在 `~/.cache/puttyplus-zig/`，**不动系统目录、不改 PATH**，删掉即卸载：

```bash
mkdir -p ~/.cache/puttyplus-zig/bin
# 从 PyPI 的 ziglang wheel 取（官方 Zig 发行版的 Linux x86_64 构建）：
#   https://pypi.org/project/ziglang/
#   ziglang-0.17.1-py3-none-manylinux_2_12_x86_64.whl
# 解压后把里面的 zig 放进 bin/ 即可
~/.cache/puttyplus-zig/bin/zig version   # 应为 0.17.1
```

构建时告诉 cargo 去哪找：

```bash
export ZIG=$HOME/.cache/puttyplus-zig/bin/zig
```

### Windows（CI）

CI 的 `windows-latest` runner 里用官方 tarball 即可
（`https://ziglang.org/download/0.17.1/zig-windows-x86_64-0.17.1.zip`），
解包后把目录加进 `PATH`。

## 4. 编译

### Linux（默认，**不需要 Zig**）

```bash
cargo build --release
```

`ghostty` 特性默认**关闭** ⇒ 日常构建、CI 的 Linux job 都不碰 Zig。

### 打开 ghostty 引擎（Linux 上也能编）

```bash
ZIG=$HOME/.cache/puttyplus-zig/bin/zig cargo build --features ghostty
```

内核冒烟：

```bash
ZIG=$HOME/.cache/puttyplus-zig/bin/zig cargo run --example ghostty_vt_smoke --features ghostty
```

### Windows

```bash
cargo build --release --target x86_64-pc-windows-msvc --features ghostty
```

⚠️ **MSVC 静态链接的坑**：`ghostty-vt-sys` 在 Windows 上产出的是
`ghostty-vt-static.lib`（静态库），**不是** `ghostty-vt.lib`
（后者是 DLL 的导入库，链错了会得到一堆找不到符号的链接错误）。
crate 的 build.rs 已经按目标平台选对了名字，别手改。

⚠️ 目标三元组 `x86_64-pc-windows-msvc` 需要装 Rust 的 MSVC 工具链
（`rustup target add x86_64-pc-windows-msvc`）与 Visual Studio 的
C++ 生成工具。

## 5. 已知限制（首版范围）

- **Windows 首版只有**：终端会话 + SFTP 文件面板 + 命令行契约。
- **数据库工作台**：在 Windows 上保留编译但**隐藏入口**（未验证）。
- **桌面通知**：Windows 首版不做（状态栏兜底已存在）。
- **中文输入（IME）**：阶段 C3 单独验收——自绘控件要自己挂
  `gtk::IMMulticontext`，兜底方案是隐藏 `gtk::Text` 代理。
- **命令行契约**：6 条含 `/home/<ME>` 路径的用例在 Windows 上做
  **归一化**（基准真值不动）。
