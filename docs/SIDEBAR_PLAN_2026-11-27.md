# 侧边栏改造计划：主窗口左栏 = [连接 | 文件]（2026-11-27）

> **一句话**：把「文件管理器」和「连接管理器」收进**主窗口左边固定的一栏**，
> 用页签切换；**连接页里的文件格删掉** ⇒ 终端占满整页宽。
>
> **已拍板**（用户 2026-11-27，问卷确认）：
> 1. 侧边栏放**主窗口左栏**（固定、跨连接、不会被拖到别处）；
> 2. 折叠 = **整栏收起**，展开时**回到上次看的页签**。
>
> ⚠️ **本文档只做计划，不改代码。** 实施从**阶段 177** 起。

## 0. 为什么要做（三个硬事实）

| # | 事实 | 出处 | 后果 |
|---|---|---|---|
| 0.1 | 主窗口默认 **1200×780**；左边「会话侧边栏」默认 **230px**（上限 320） | `src/main.rs:139,151–160`；`src/settings.rs:522–533` | — |

## 2. 改动清单（按文件）

### 2.1 新增：`src/sidebarhost.rs`（侧边栏外壳）

一个 `SidebarHost`，装下**页签栏 + 两个页**：

```rust
pub struct SidebarHost {
    pub root: gtk::Box,      // 竖向：页签栏（Notebook）+ 内容
    pub nb: gtk::Notebook,   // 两页：「连接」/「文件」
    pub files_slot: gtk::Box,// 「文件」页的槽位（文件面板塞这里）
}
```

| 决策 | 取法 | 为什么 |
|---|---|---|
| 页签容器 | **`gtk::Notebook`** | 项目里到处是 Notebook（`SubTabs.nb`）；页签图标/文字/tooltip 行为一致；切页一行 `set_visible_page` |
| 不用 `Stack`+`StackSwitcher` | — | StackSwitcher 的样式跟项目现有页签栏**不一致** ⇒ 两套外观 |
| 「连接」页内容 | **现有 `Sidebar::widget` 整块搬进来** | 连接管理的 UI **一个字不改** ⇒ 不引入第二套 CRUD（阶段 77a/77b 的决定不能推翻） |

⚠️ **`Sidebar` 实例保留**：顶栏要拿它的凭据库状态标志（`topbar.rs:188,508`）⇒
不要把它拆散，只换**挂载位置**。

## 5. 风险与已知取舍（**明说放弃了什么**）

### 5.1 ⚠️ 放弃「文件面板可拖成独立格」（阶段 146 的能力）

文件面板不再是格子树里的一个页 ⇒ **用户不能把它拖到单独一格**了。

- **为什么可以接受**：默认布局本来就是「文件 ｜ 终端」两格 ⇒ **视觉上零损失**；
  被牺牲的是"再拆一格"的自由度。
- **如果以后要找回**：得让侧边栏的「文件」页与格子树里的 Files 页**共享同一个
  `PanelState`**（不是同一个 widget）⇒ GTK4 一个 widget 一个父级的限制还在
  ⇒ 需要"显示哪一份"的仲裁 ⇒ **不是小改动**。

### 5.2 折叠后**看不到文件面板**

已拍板「整栏收起」⇒ 折叠期间文件面板不可见（今天折叠侧栏不影响文件面板）。
⇒ 缓解：折叠按钮放在**侧边栏页签栏**里（收起后页签栏也不见了 ⇒ 只能从顶栏的
开关恢复）⇒ 顶栏那个开关**必须保留**。

### 5.3 「连接」页签在**主窗口级** ⇒ 只有一份

好处：不会出现 N 份连接树（N 份要各自刷新、各自右键菜单、各自空态）。
代价：**连接树是全局的** ⇒ 它不随连接 tab 变（这是对的）。

### 5.4 文件面板**跨连接共享同一个侧边栏槽位**

每个连接 tab 各自有自己的 `st.root`（per-会话，worker 绑会话）⇒ 侧边栏的
「文件」页**装的是当前活动连接的那一份** ⇒ 切 tab 时**搬家**（复用现有
`host_file_panel` 的"先清旧槽位再挂新的"）。

⚠️ **代价**：同时开着 3 台机器时，侧边栏只看得到**当前那一台**的文件
⇒ 今天也一样（文件面板本来就在当前终端子页里）⇒ **不新增损失**。

### 5.5 阶段 178 是**过渡态**（两处都有文件面板）

文件格还没删的那一步，界面上会**同时出现两个文件面板** ⇒ 该阶段的冒烟只断言
"侧边栏里那个是对的"，**不要**断言"只有一个文件面板"。
