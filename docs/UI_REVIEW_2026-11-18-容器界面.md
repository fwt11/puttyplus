## 0. 一句话

容器工作台的**骨架是对的**（树形分组 / 共享连接 / 刷新保选中 / loading 动画 /
启停按钮按状态置灰），但**界面层像是"功能做完就交差"**：监控页在暗色主题下是
四个白盒子、在默认窗口高度下有一半在屏幕外；四张曲线没有标题没有刻度没有图例；
表格不能排序、不能右键、不能键盘操作；空列表和连不上时都只剩"一张空表 + 一行
小灰字"。

**最刺眼的三件事**：

1. **暗色主题下监控曲线是白底**（`cr.set_source_rgb(1.0,1.0,1.0)` 写死）
   ⇒ 这正是 `docs/UI_AUDIT.md` §S1 记过的"硬编码色"老问题，**新功能又犯了一遍**；
2. **监控页在默认窗口高度下显示不全** ⇒ 第二行（网络 / 磁盘）整行在窗口外；
3. **容器表格不能排序、不能右键、不能键盘操作** ⇒ 一个监控表格失去了监控表格
   一半的本事。

| 维度 | 评分 | 一句话 |
|---|---|---|
| 信息架构 | 3/5 | 四段 + 四个子页的层级清楚；但工具条挤了 11 个控件，刷新按钮有两个 |
| 视觉层级 | 2/5 | 「概览」是四坨纯文本不是卡片；4 张图没有标题 |
| 一致性 | 2/5 | 容器页有搜索框，镜像/卷/网络页没有；图标按钮与文字按钮混排 |
| 可发现性 | 2/5 | 进 shell 靠双击（无提示）；写操作全在详情区 |

## 2. P0 —— 真的坏掉

### D1　暗色主题下，4 张监控曲线是四个**白盒子**

**证据**：`docs/ui-review-2026-11-18-docker/dark-2-monitor.png`
（暗色面板上并排两个刺眼白块，网格线几乎看不见）。

**根因**：`src/panel/dockerui.rs:585` `cr.set_source_rgb(1.0, 1.0, 1.0)` 写死白底；
边框 `0.62` 灰（:588）、网格线 `0.75` 灰（:593）、单位文字 `0.35` 灰（:633）
同样写死。**cairo 画的东西不过 CSS**，所以 `theme.rs` 那套主题对它无效。

项目明明有 `Theme::Dark`（`theme.rs:37`）与高对比主题，容器工作台是 v0.9.0 的
新功能 —— 等于**最新的一块界面没跟上项目已经建立的规矩**。

**修法**：曲线底色/网格/文字取当前主题的面板色（`theme.rs` 已有 `state_hex`
那一套语义色入口，或从 `StyleContext` 查 `.background-color`）；
画线颜色也走 CSS 变量取出来的 RGBA，别再写 RGB 常量。

### D2　监控页在默认窗口高度下**显示不全**

**证据**：`size-1200x780-monitor.png` —— 这是按**主窗默认尺寸 1200×780**
（`src/main.rs:132`）复核的：第二行图（网络 / 磁盘）只露出上边框，
曲线整条在窗口外。

**算得也对**：详情区起点是**写死的** `paned.set_position(360)`
（`dockerui.rs:2122`）⇒ 详情区高度 = 窗口高 − 360。而监控页要放
指标卡 ≈40 + 页签条 ≈40 + 标题行 ≈30 + 两行图（每张 `content_height(120)`
+ 行距 6）≈ 362 ⇒ **需要 ≈420px**。窗口 780 高时详情区只有 ≈400px，
**刚好差一点**；而真实主窗里容器页还要再扣掉顶栏 / 侧边栏 / 标签栏 ⇒
比测试窗口更矮 ⇒ 实机更看不全。

**修法**（三选一，建议第一个）：① 监控页自己带滚动容器；② 4 张图改成
"一张大图 + 上方 4 个可切换的指标按钮"；③ `paned.set_position` 改成按内容
算（或给详情区一个更小的默认起点，列表自己可滚）。

### D3　4 张曲线**没有标题、没有 Y 轴刻度、没有图例**

* `mk_chart`（:1846）只造了一个裸 `DrawingArea` —— **没有标题 label**；
* `draw_chart`（:566）只画了 3 条网格线 + 曲线 + 左下角一个单位（`%` / `B/s`）
  —— **Y 轴自动量程但一个数字都不标**；
* 网络/磁盘各画 2 条线（收/发），用 4 种颜色区分，**没有图例**。

⇒ 一屏四个框，用户要靠猜：哪张是 CPU？曲线冲顶是 5% 还是 50%？橙线是收还是发？

**修法**：每张图加标题（CPU% / 内存% / 网络 / 磁盘）；Y 轴标最大值与 0；
两条线的图加一个 2 色小图例。

## 3. P1 —— 很难用

### D4　容器表格**不能排序**

全文件没有一处 `set_sort_column_id`。CPU、内存两列明晃晃摆在那儿，**用户唯一
能做的就是用眼睛扫**找最占资源的那个 —— 而这恰恰是"容器监控"最核心的动作。

**修法**：`view.set_sort_column_id` + `set_sort_func`（按数值排序，别按字符串：
"9.5%" 排在 "50.8%" 前面是字符串排序的经典坑）。

### D5　没有右键菜单，没有键盘操作

全文件没有 `connect_button_press_event`、没有 `connect_key_press`。

* 写操作（启停 / 重启 / 进 shell）**只能**靠"选中行 → 看下半区详情 → 点按钮"；
* 想在 20 个容器里停掉一个 ⇒ 先滚动、再选中、再够到下半区、再点；
* 「双击顶层容器行进 shell」是**没有提示的隐藏交互**（唯一线索是按钮 tooltip）。

**修法**：行右键菜单（进 shell / 日志 / 启停 / 重启 / 复制 ID）；
键盘（↑↓ 选行、Enter 进 shell、Del 停止、`/` 聚焦搜索框）；双击行为在界面上
给一行提示文字。

### D6　空态与错态：一张空表 + 一行小灰字

* `fail()`（:883）＝清空模型 + 在**底部状态行**写一句话；
* 列表区此时是**纯白/纯黑的一块**（`dark-4-error.png`、`docker-expanded.png`）。

最常见的三个"第一分钟错误"——远端没装 docker、当前账号不在 docker 组、
docker 守护进程没起 —— 在界面上**长得一模一样**。

⚠️ 项目里**已经有** `src/emptystate.rs`（侧栏、私钥管理器在用，`emptystate::build`），
容器页没接。（数据库工作台是**故意**不接的 —— `dbui.rs:5129` 说明它那里
"没有可做的动作，硬塞按钮是噪声"；但容器页**有**现成的真动作：重试 / 刷新
⇒ 直接能用上。）

**修法**：接 `emptystate`，按后端错误分类给不同文案（`backend/docker.rs`
里已经有 `shell_probe_error_msg` 那种分类函数可复用），主 CTA 给「重试」。

### D7　状态行在说假话 / 说旧话

**(a) 数字对不上**：`apply()`（:871）写的是 `共 {info.containers.len()} 个容器`
—— 那是**过滤前**的总数；表格里显示的是过滤后的行数。点「运行中」只剩 1 行，
底栏还写着「共 2 个容器」。

**(b) 内容是旧的**：状态行是**整页共用**的。切到「文件」页后，底部仍挂着
「正在读取远程容器…」—— 见 `docker-files.png` 最下面那行；
切到「镜像」页则是「正在读取远程镜像…」。**上一段的状态污染下一段**。

**修法**：每个分段/子页各有自己的状态；过滤时写成「显示 1 / 共 2」。

### D8　容器状态是纯文字，没有色彩/图标

状态列只有「运行中」/「已停止」几个字（`state_label()`，`backend/docker.rs:1213`）。
对标设计（dbx）是**绿点/灰点 + 文字**。一屏 30 个容器时，"哪些在跑"要逐行读字。

**修法**：状态列改用带色点的渲染器；颜色走 `theme::state_hex`（项目已有）。

### D9　「概览」页是四坨纯文本，不是四张卡片

计划书（`tools/DOCKER_PLAN.md` 阶段 110）写的是"四张卡片（2×2 网格）"，
实际实现是 `mk_card`（:1743）＝**标题 Label + 一个可换行的纯文本 Label**：
没有 key/value 对齐、没有分隔线、没有边框。

**而且挤在一起会互相裁**：截图 `dark-3-overview.png` 里「运行用户：root」
这行**被下面「挂载」标题压掉一半**（`Grid` 行高自适应 + 卡片正文可滚）。

**修法**：改成真正的键值表（每行：键 | 值），别塞成一坨自动换行的文本。

### D10　日志长行被截断，且看不到横向滚动条

`log_view.set_wrap_mode(gtk::WrapMode::None)`（:1787）是有意为之（免得时间戳和
正文被折行拆散），但**横向滚动条在界面上看不见** ⇒ 长行尾部就这么没了
（`docker-log.png` 里 `…0 WAL file(s) added, 0 removed, 0 rec` 断在那里）。

**修法**：加「折行」开关（默认关）；或让横向滚动条常显；补一个「复制全部」。

### D11　文件页：目录的大小是 4.0 KB；权限是原始八进制

* 每个目录都显示 `4.0 KB`（那是 inode 大小，纯噪音）⇒ docker 官方与 dbx 都给「—」；
* 权限列给 `drwxr-xr-x` 原始八进制 —— Windows 用户看不懂，也没走 `tr()`。

### D12　镜像/卷/网络三页**没有任何筛选**

容器页有搜索框，这三页没有。本机 44 个镜像里 30 个是 `eng-tut-backend` 的重复
tag，仓库列重复 30 遍（`docker-images.png`）；真实服务器上镜像轻松上百个。
创建时间列还带 `+0800 CST` 后缀，白占 170px。

### D13　工具条一行塞了 11 个控件

```
[搜索容器(可拉伸)] [全部][运行中][已停止] [上次刷新 19:38:13] [自动刷新][开关] [转圈] [进入容器] [↻]
```

* 「上次刷新 19:38:13」（dim-label）**紧贴**「自动刷新」四个字，中间零间距
  —— 见 `docker-log.png` 顶部，"上次刷新 19:38:13 自动刷新"几乎连成一片；
* **两个刷新按钮**：分段栏右边一个 ↻、工具条最右又一个 ↻ —— 在「容器」段里
  它俩干的是同一件事；
* 搜索框 `set_hexpand(true)` 把右边的控件全推走，窗口一窄就溢出（Box 不换行）。

**修法**：刷新按钮只留一个（分段栏那个）；「上次刷新」挪到状态行，跟
「共 N 个容器」放一起；工具条拆成「筛选组 | 操作组」两块，窄时折叠成 ⋯ 菜单。

## 5. 修复顺序建议

| 批次 | 内容 | 理由 |
|---|---|---|
| **第一批** | D1（曲线取主题色）+ D3（标题/刻度/图例） | 一眼可见的破相，且改动集中在 `draw_chart` 一个函数 |
| **第二批** | D2（监控页布局）+ D6（空/错态接 `emptystate`） | 影响"能不能用"，不涉及重构 |
| **第三批** | D4（排序）+ D5（右键/键盘）+ D8（状态色点） | 把容器表格变成真正的监控表格 |
| **第四批** | D7（状态行）+ D13（工具条瘦身）+ D9（概览改键值表） | 信息层级与密度 |
| **零散** | D10 / D11 / D12 / D14 / D15 / D16 / D17 / D18 / D19 / D20 / D21 | 逐条清 |

> ⚠️ 按项目规矩（`docs/UI_AUDIT.md` §S1）：**语义色必须走 CSS 变量或
> `theme::state_hex`**，不要再写 RGB 常量 —— 否则暗色/高对比主题下又会崩一遍。
