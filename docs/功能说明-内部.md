# PuTTYPlus（Rust 重构版）

本目录是 PuTTYPlus 的 Rust 重构版：与 C 版（`../src/`）行为 1:1 兼容，
技术栈换为 **GTK4 + vte4 + russh + russh-sftp**。

## 编译

```bash
# Deepin/Debian/Ubuntu（GTK4 与 VTE-GTK4 开发包）
sudo apt install build-essential pkg-config cargo \
    libgtk-4-dev libvte-2.91-gtk4-dev
cargo build --release
# 产出 target/release/puttyplus（约 2.7MB）
```

发布配置（`[profile.release]`）已含 strip / fat LTO / `opt-level="s"` /
`panic="abort"`，并把 russh 的 crypto 后端从默认 aws-lc-rs 换成更精简的
ring。二进制比 C 版（115KB）大是因为 SSH 协议栈与加密库在 C 版是共享库
（libssh + libcrypto），Rust 版全部静态打进单一文件——部署时反而**不依赖**
libssh/libcrypto，只需 GTK4/VTE4 运行库。

`cargo test` 运行全部单元测试（参数解析 / ssh config / PuTTY 会话 /
known_hosts / connections.ini 存储等纯逻辑层）。

## 打包成 deb

`debian/` 是标准的 Debian 打包目录（MIT 许可），一条命令出包：

```bash
bash rust/tools/build_deb.sh            # 只打包
bash rust/tools/build_deb.sh --test     # 先跑单元测试再打包
```

产物落在仓库根目录：`puttyplus_<版本>-1_amd64.deb`（约 1.8MB，
安装后 5.4MB）。安装：

```bash
sudo dpkg -i puttyplus_<版本>-1_amd64.deb
```

包里装了什么：

| 路径 | 内容 |
| --- | --- |
| `/usr/bin/puttyplus` | 主程序（单二进制，SSH/crypto 全静态） |
| `/usr/share/applications/puttyplus.desktop` | 桌面菜单项 |
| `/usr/share/icons/hicolor/{16,24,48,64,128}x128/apps/` | 图标（取自 `src/appicon.rs` 里内嵌的那张 PNG） |
| `/usr/share/man/man1/puttyplus.1` | 中文手册页 |
| `/usr/share/doc/puttyplus/` | README、changelog、copyright |

依赖声明由 `dpkg-shlibdeps` 按实际链接的库自动算出，并额外锁死
GTK ≥ 4.18、VTE ≥ 0.80（对应 `Cargo.toml` 的 `v4_18` / `v0_80` 特性）；
glib 写成 `libglib2.0-0t64 | libglib2.0-0` 二选一，Debian 13 /
Ubuntu 25.04+ / Deepin 25 都能装。

自己改过 `debian/` 里的东西之后，可以用 `dpkg-buildpackage -us -uc -b`
直接重出包（等价于上面脚本里的最后一步）。注意本机 cargo 来自 rustup
而不是 dpkg，`dpkg-checkbuilddeps` 会误报「缺 cargo」，脚本用 `-d`
跳过这一项校验；apt 里的 cargo 是 1.81，编不了 edition 2024。

### 发布到发行版仓库时

当前 `debian/source/format` 是 `3.0 (quilt)`，出源码包需要先准备
`puttyplus_0.1.0.orig.tar.gz`；只出二进制包（`-b`）不需要。


## 界面（Rust 版）

多标签主窗：左侧会话侧边栏（最近/自定义/ssh config 分组、过滤框、双击即连），
右侧每标签一套「SFTP 双栏 + 终端」。快捷键：Ctrl+Shift+T 新建标签、
Ctrl+Shift+W 关闭标签、Ctrl+F 终端查找、Ctrl+Shift+C/V 复制粘贴。

**连接页里还有一层子标签**（对标 XTerminal 的两层标签）：连接 tab 下面挂着
终端、**数据库工作台**、文件编辑器——它们是**平级的子标签**，不再是各自
独立的弹窗。**阶段 98 之后**：**文件面板跟着「当前那一页」走**（它在
**终端页与编辑器页的内部**），连接页只剩子标签区，切到数据库页时那一页
**整页替换**：

```text
主窗口
├── 标签栏：连接 tab（aly ×   +）
└── 当前连接页（只有子标签区）
    ├── 子标签栏（终端 / 数据库 / .zshrc …）
    └── 当前子页：
        ├── 终端页：横向 Paned（左＝文件面板，右＝终端）
        ├── 编辑器页：横向 Paned（左＝文件面板，右＝编辑器）
        └── 数据库页：整页替换（对象树 + 结果区 + SQL 编辑器）
```

**阶段 98**：**文本编辑页也带上文件面板**（用户 2026-11-06 要求）——编辑远程
文件时左边照样能翻目录、点别的文件换着编辑，不用来回切页签。
⇒ 编辑器页的内容包一层 Paned（左＝文件面板 / 右＝编辑器），
`PageKind::FileEdit` 也成了"能托管文件面板"的那类页
（`src/tabs.rs` 的 `switch-page` 处理器里，Terminal 与 FileEdit 都搬）。

**阶段 97 的根因与修法**（用户 2026-11-05 截图报的现象）：文件面板原先住在
**连接页那一层**（子标签区左边）⇒ 切到数据库页时它还占着 340px，而 GTK4 的
`Paned` **把空间给 end child**（`set_visible(false)` 就够）⇒ **子标签栏的
左边界从 340 跳到 0** ⇒ 整排页签头左右乱晃，看着像界面坏了。
⇒ 修法：文件面板**搬进子页签**（`src/panel/mod.rs` 的 `host_file_panel()`：
先 `set_start_child(None)` 让旧框让出槽位，再挂新宿主，按 `st.file_w` 复位
宽度；`track_file_width()` 负责把拖拽宽度同步回 `file_w`）。
**同时撤掉了「显示 / 隐藏文件面板」开关**（0.3.2 引入的那套会话内显隐）。

⚠️ **宿主 Paned 必须有人强引用**（`PanelState::file_host`）：GTK4 里容器被
finalize 时会把它子控件一起 `gtk_widget_destroy` ⇒ 宿主页签一关，文件面板
就跟着没了（Rust 侧那个引用救不回来——widget 已被标成"不可再用"）。
留一份强引用 ⇒ 宿主不会被 finalize ⇒ 文件面板安全等到下一次搬家。

改成子标签是为了**把空间让出来**：数据库工作台原来是弹窗，1100px 的窗口
里一半给了对象树，剩下的一半要塞结果网格和 SQL 编辑器，工具栏一排图标
按钮都被切掉了；现在它占满整个子标签区。文件编辑器同理，它的标题栏从
「窗口标题栏」变成了「页内第一块」（保存 / 刷新按钮跟着页面走），标题前面
的 `●` 表示有未保存的修改，关页签时会先问「保存 / 不保存 / 取消」。

**标签头上不放图标**（阶段 27）：主标签头只剩 `[状态点][标题][×]`——原先
常驻的「快速命令」「数据库」两个图标按钮挤在标题后面，把标题压成省略号。
图标改挂在**子标签**上（终端 / 数据库 / 文件编辑器各一个），「这一页是什么」
由子页签自己说；文件编辑器那个页签**不再写「编辑」**，只留 `● 文件名`，
编辑还是查看靠图标区分。

**子标签栏最右端有个「+」**：菜单两项——「**新建终端**」（在当前连接里再开
一条**独立**的 SSH 会话，作为平级的另一个终端页签）和「**新建数据库连接…**」
（会话预置死，建好直接连上）。按钮是**浮**在页签栏上的，不占布局宽度
（排成独立一列的话，软件右边会多出一条空荡荡的竖带）。

**终端没了能救回来**（阶段 26）：会话结束（敲了 `exit`、网络断了）之后，终端
区会摆出一条「**会话已结束 · 点此重新连接**」——以前只在终端里打一行字提示，
多数用户看不出"还能救"。另外：

- 标签头**右键菜单**有「重新连接终端」（与「重新连接 SFTP」并列）。这俩是
  **两条链路**：SFTP 走进程内通道，终端是另起的 ssh 子进程，点「重新连接
  SFTP」救不了已经 exit 的终端；
- 终端子页签被 × 关掉之后，「重新连接终端」会**重建**一个终端页签出来
  （不然重连的是一个用户看不见的会话，点了像没反应）；
- 整个连接标签被关掉之后，**会话树右键**有「重新连接终端」，用同一份连接
  参数把标签重建出来。

**断线自愈（阶段 99，用户 2026-11-06 明确要求）**：用户原话——
「就是在异常处理程序中重连一次，如果还是失败就报错，否则就继续执行原来的
操作」+「终端和数据库里面也可以这样处理」。落成三条链路（SFTP / 终端 /
数据库），**同一套形状**：

- **失败分两类**（地基）：「连接断了」⇒ 可自愈；「服务器说不行」（权限不足、
  重名、SQL 写错）⇒ **只能报错**，重试也是同样的错。
  ⚠️ **判定用 worker 共享标志（`PanelState::conn_dead: Arc<AtomicBool>`）+ UI
  自己的 `conn_ok`，不靠匹配错误文案**（文案会翻译、会改）。
  ⚠️ **worker 必须在发事件之前把标志写好**（`worker.rs::send_ev`）⇒ UI 读到
  的一定是那一刻的真实状态。反过来 ⇒ 读到旧值 ⇒ 误判 / 漏判。
  ⚠️ 数据库为此新增**结构化事件** `PanelEvent::DbLost { id }`（替换 8 处
  「数据库连接已断开」的 `DbError` 文案事件）——数据库靠**事件类型**判「断了」。
- **只重试一次**（`PanelState::retried` 闸门）：用户说的是「重连**一次**」。
  没有闸门 ⇒ 重连成功、重试又失败 ⇒ 又重连 ⇒ **无限循环**。
  ⚠️ **闸门什么时候清，三种情况**（阶段 99 实测踩出来的）：
  ① **操作成功了** ⇒ 清（**不清的话**：自愈成功一次之后闸门一直挂着 ⇒ 之后
     **每一次**断线都被当成「重试后又失败」⇒ 永远不再重连）；
  ② **重连本身失败了** ⇒ 也清（那次没进「重连成功 ⇒ 重试又失败」的循环 ⇒
     不该占着用户的额度，否则用户下一次操作只会看到一个错、连重连都不发起）；
  ③ **重试又失败了** ⇒ 清（这时才报给用户）。
- **重发什么按种类记**（`retry_ops: HashMap<RetryKind, RetryOp>`）：失败事件只带
  「路径」，**够不着一条完整命令**（「重命名」要知道改成什么名、「写文件」要
  知道内容）⇒ **发命令时把整条命令记下来**，失败时按种类取出来重发。
- ⚠️ **「记住的那条」不一定就是「失败的那条」**（阶段 99 复查时发现的竞态）：
  `retry_ops` 记的是**最后一次发出去**的，中间插进来一条后台刷新（终端目录
  跟随 / 远端目录 mtime 变化触发的**静默列目录**）就会改写它 ⇒ 重试的变成
  别的目录 / 别的文件。
  ⇒ **列目录**：失败事件**自带路径**（`Listed { path }`）⇒ 直接拿它重发；
  **其余种类**（失败事件里没有内容）⇒ **核对路径对不对得上**
  （`retry_op_matches` 纯函数 + 单测），对不上就**不重试**（重试错的那条 =
  替用户干了别的事）。
- ⚠️ **状态顺序**：`schedule_retry()` 是**先重连、后写状态**——`on_reconnect()`
  自己也会写状态，写在它后面就把「连接已断开，正在重新连接…」盖掉了。
- ⚠️ **数据库只对「查询」做「重连 + 重试原查询」**：翻页 / 元数据 / 写语句
  **只重连不重试**（游标已挪动，重发会翻错页）。
- ⚠️ **数据库自愈重连必须保住结果页签**（`dbui::clear_tabs(ui, keep_pages)`）：
  重连走 `do_connect` ⇒ 它会 `clear_tabs`（**结果页签 + 待办表全清**）⇒
  断线时失败的那条查询**重发回去也没有地方放结果**（回包按待办表找落点，
  找不到就把结果丢了）⇒ 自愈走 `do_connect_inner(..., keep_pages = true)`，
  重发时**补登记待办**（`pending[id] = Query{tab_id, sql}`）。
  ⚠️ 页签被清掉时 `ui.docs` / `ui.struct_tabs` 要一起清（阶段 72e 的老坑）；
  **保住页签**时文档还活着 ⇒ 不用清。**待办表任何情况下都要清**。
- **终端的「原操作」= 用户在会话死后敲的输入**：用现成 `encode_key()` 采集
  （**不要用 VTE 的 `commit` 信号**——有 pty child 时压根不触发），存
  `TermInner::pending_input`，**等看见提示符（`ReadyCmd::Cmd`）之后**再补发
  —— Probe 阶段就发会被登录脚本当成登录名吃掉。
- **点「重新连接终端」顺带救 SFTP**（用户 2026-11-06 报的就是这个）：
  `panel::reconnect_sftp_if_dead`（**幂等**，`connecting` 挡着）。
  终端自带的「会话已结束 · 点此重新连接」走同一个 `reconnect_hook` ⇒ 也救。
  ⇒ 三处终端创建点都装钩子：`Tabs::open` / `new_term_page` / `rebuild_term`。
- **冒烟**：`examples/selfheal_smoke.rs`（10 步，已进 CI 清单）：SFTP 失败⇒自动重连 / **上次重连失败⇒下一次操作照样发起重连** / 连上⇒重发原操作 / 重试又失败⇒不再重连 / 数据库 `DbLost`⇒重连 / 连上⇒重发查询（**待办已补登记**）/ **自愈成功⇒闸门清掉⇒下次断线照样自愈** / 重连终端⇒SFTP 也重连。

连接菜单 / 标签右键 / `Ctrl+Shift+D` 还有「数据库」窗口：**对象浏览器 + 多
结果页签 + 可编辑数据网格**（形态对标 DBeaver / Navicat）。左边是对象树
（模式 → 表/视图 → 列/索引，**展开才查**，不一次性拉全库元数据），双击一张
表就开一个数据页签；右边每次执行 SQL 开一个新页签（`Ctrl+Enter` 执行，
`Ctrl+Shift+Enter` 只跑选中的那段），页签里能**排序**（点列头）、**筛选**
（行内包含关键字）、**导出 CSV**（Excel 友好，带 BOM）。

数据编辑是**显式动作**：点「编辑」才开事务、才允许改单元格；「保存修改」把
每行拼成 UPDATE 执行（WHERE 用主键；没有主键就用整行原值定位），**全部成功
才 COMMIT，任何一条失败就 ROLLBACK**——绝不自动提交。视图不能编辑。改动
的值按列类型转字面量（整数/数字/布尔会先在本地校验，填错直接报中文原因）。

SQL 编辑器旁边有个**「历史」按钮**：跑过的语句留档（按「会话 + 数据库连接」
分开存，`~/.config/puttyplus/history.ini`——一个 SSH 会话下挂了几个库，历史
就是分开的），双击一条就把它填回编辑器——**不自动执行**，看一眼确认了再点
「执行」。同一条 SQL 连着跑不会在历史里堆出一串一样的行。

底层复用当前 SSH 连接（不新建连接、不占固定端口），支持 PostgreSQL /
MySQL；连接配置存 `databases.ini`，密码可选存凭据库。SQL 编辑器带语法
高亮（复用文件编辑器那套分词器，规则只有一份）。

**要密码时弹框问**（2026-10 修）：服务端要口令、而这条连接没带密码时（凭据库
当时锁着、密码没存上就会这样），会**弹一个密码框**让用户当场输，输完自动
重连；可以勾「记住密码」存进凭据库。之前这里只甩一句驱动原文
`invalid configuration`，用户完全看不懂。

**双击就连上**（阶段 22）：双击会话树 / 连接管理器里的数据库连接 → **直接连上**，
不用再在工作台里点一次「连接」。服务端要密码就**弹框问**，输完自动重连。

**凭据库忘了主密码？有出路**（阶段 30）：主密码是解锁凭据库的**唯一**钥匙，
忘了它（或者文件损坏）里面保存的密码就再也解不开——**没有后门**，这是密码学
的必然。所以解锁框里多一颗「**忘记主密码？重置凭据库**」：密码输错时**对话框
不关**（就地显示红色错误并指路，当场就能改密码重试或转重置），重置分两步
（先摆清"会丢什么 / 不会丢什么"再要新主密码）。重置 = 丢掉旧库、用新主密码建
一个**空**库：旧密码**永久丢失**，但**连接列表、数据库连接定义、「记住密码」
的勾选都不受影响**——要做的只是**重新输一遍**密码，不是"重建一切"。

**凭据库管理器**（阶段 31）：连接管理器底部的「凭据库…」按钮打开一个管理
窗口，**列出库里有哪些连接名、各自属于哪个会话**（解锁完原先只提示一句
"已解锁"，用户什么也看不到），外加四个动作：**改主密码 / 重置凭据库 /
锁定 / 关闭**。改主密码把凭据一条不少地搬过去（旧密码错则拒绝，文件不动）。

也可以**不设主密码**：勾「不设主密码（不加密保存）」→ 凭据**明文**存文件里，
文件头**明写 `protected=false`**——一眼就能看出这份库**没加密**，而不是看到
一堆 base64 就以为它是安全的。（⚠️ 选了就不加密，这是明说的取舍；改成加密
状态走「改主密码」，降级成明文要走「重置」。）

**凭据库状态一直看得见**（阶段 33）：凭据库是「**开了才生效**」的开关，
而**开了没有、密码存到哪去了，全靠用户自己记得**——忘了自己没开，就会以为
「记住密码」把密码加密存起来了，其实它**明文躺在 `connections.ini` 里**。
所以顶栏常驻一个标志，一眼就知道当前是什么状态：

| 标志 | 含义 |
|---|---|
| 🔑 凭据库 未启用 | 还没建库。勾「记住密码」时密码会**明文**写进 `connections.ini` |
| 凭据库 已启用（绿） | 已建库、有主密码、当前已解锁：密码加密存在本机 |
| 凭据库 已锁定（黄） | 已建库、有主密码，但**锁着**（重启后的常态：主密码不跨进程保存） |
| ⚠ 凭据库 未加密（红） | 已建库但**没有主密码**：密码明文躺在本机文件里 |

点它直接打开凭据库管理器；**连接管理器**顶部也有同一个标志（那是勾
「记住密码」的地方），两个菜单项的标题也带状态（「凭据库…（未启用）」）。

**堡垒机场景里「记住密码」一个地方都不出现**（用户 2026-11-03）：
堡垒机的 launcher 从命令行拉起本程序，那种连接是**一次性**的（用户刻意
不保存 ⇒ 不在连接列表里）⇒ 这类会话里「记住密码」**整个不显示**。
判定只看一条：**这个会话在不在连接列表里**（`dbconn::is_bastion_session`
⇒ `session_choices()` 里找不到它）；在列表里的 = 用户自己管理的普通连接，
照旧按凭据库状态显示（`Off`/`Locked` 不显示，`Plain`/`Unlocked` 显示）。
覆盖三处入口：`dbconn::ui_new` / `dbconn::ui_edit`（两个独立勾选框）、
`dialogs::ask_password_remember`（连库时的密码提示框）。

**工作台里没有连接信息**（阶段 13 + 22）：连接信息在**连接管理器**和**会话树**里
维护，那里也是一棵树——数据库连接**挂在对应的 SSH 连接下面**：

```text
连接管理器 / 会话树
├── 跳板机 (aly)
│   ├── 本地 PG（pg 127.0.0.1:5432/postgres）
│   └── 测试 MySQL（mysql 127.0.0.1:3306/demo）
└── 另一台服务器
```

新建连接时**先选数据库类型**（PG / MySQL），然后填地址 / 端口 / 用户 / 库 /
密码。**会话是定死的**（阶段 29）：对话框里**没有**「在哪个会话上连」的下拉
框——所有入口（「+」、标签头右键、会话树右键、连接管理器右键）都把会话**预置
死**了，"从哪儿来就属于哪儿"。要换宿主就**切到别的 tab 再点「+」**。

**对话框里敲的密码，这次连接就直接用**（阶段 34）：不勾「记住密码」也照样
用——密码**不落盘**（不该偷偷存），但**连这一次**当然要用它。以前它被直接
丢掉了，工作台连库时只能**再弹一次密码框**问一遍（"刚才不是刚输过吗"），
看着就像密码框根本没生效。密码框留空则不塞空密码。

对话框的按钮是「**连接**」不是「保存」（阶段 29）：所有入口建完都**立刻连上
并打开工作台**，写「保存」是误导——堡垒机场景下会话本身都没保存，"保存"既
做不到也没意义。

⚠️ **堡垒机场景**（当前会话**没保存在连接列表里**——命令行连的、列表被清过）：
对话框只摆一行说明「这条连接挂在当前会话上」。这条连接跟着**当时那个会话**
走：会话在，工作台里就看得见、用得上；会话没了，它跟着一起过期。
⚠️ **不会**把这种会话塞进连接管理器——用户没保存是**刻意的**（端口/密码下次
就变，存下来是过期垃圾）。双击一个数据库连接 = 先连上它的 SSH 会话，连上后
自动打开数据库工作台并**直接连上**。

工作台里**一个连接按钮都不留**（2026-10-27）：新建走子标签栏右端的「+」
→「新建数据库连接…」（建好直接连上），断开走**关掉页签就自动断开**。
连的是哪条写在**页签头**上（"数据库 · 本地 PG"）。换连接就双击另一条——
换连接 = 断开重连。

关掉页签再打开**不用重新输密码**：当场输入的密码记在**会话**上（不是工作台
上），页签关掉也还在。

对象树**上方**有个搜索框（放大镜图标，回车触发）：**在整个库里搜对象**——表 /
视图 / 字段 / 函数 / 存储过程 / 触发器 / 事件，**跨所有模式**（PG 的模式、
MySQL 的库）。它搜的不是树上已经展开的那几层（那种树过滤只能筛用户已经点开的
东西），而是服务端一条 SQL 查全库，结果弹一个窗口出来，双击直达：表/视图开数据
页签、字段打开它所在的表、函数/过程/触发器/事件开定义页签。系统模式
（`pg_catalog` / `information_schema` / `mysql` / `sys`）会被滤掉——不滤的话搜个
常见列名（比如 `id`），`information_schema` 自己那几百个字段全冒出来；关键词里的
`%` / `_` 当普通字符处理（不然搜 `50%` 会搜出一堆不相干的）。

对象树右键还有「**表结构**」（对标 Navicat 的表设计器）：字段（类型/可空/
主键/默认值）、索引、外键三张表，外加一页可编辑的 **DDL**（由
information_schema 自己拼——PG 没有 `SHOW CREATE TABLE`；默认值一定要带上，
否则用户看一眼 DDL 再执行就把默认值弄没了）。DDL 要点「执行 DDL」才生效。

**字段表可以直接改**（阶段 14）：在「字段」那一页上双击格子就能改——列名、
类型、可空、主键、默认值；工具栏上还有「**+ 加字段**」「**− 删字段**」「
**保存修改**」「**放弃修改**」。改完点「**保存修改**」才动库，所有改动会打包成
**一条** `ALTER TABLE` 执行（所以要么全成功、要么全不动，不会出现"加了列却没
删掉列"的半截结构）。删列、改类型这类**可能丢数据**的操作会先弹确认框，框里
会把要执行的语句和风险都摆出来。**「放弃修改」**重新读一遍结构，本地改动就
没了。索引和外键那两页目前还是只读的——改索引要处理唯一性和多列组合的联动，
暂时只能手写 DDL。

**字段的顺序能调**（阶段 88）：字段表每行末尾的「操作」里有「**上移一行**」
「**下移一行**」⇒ 让新表的列按自己想的顺序来，不用再一行行往下加。⚠️ **诚实
边界**：**已有列的物理顺序 `ALTER TABLE` 改不了**（PG / MySQL 都不行，要重建表）
⇒ 改顺序改的是**列表里的排列**与**新加字段的添加顺序**（后者真生效）⇒ 预览里
「只剩顺序变了」时会明说这件事。实现：`DbGrid` 单开一层**显式行序**
（`order: RefCell<Option<Vec<RowRef>>>`，`None` = 用户没动过）⇒ **只在没有
排序时生效**（排序状态下拒绝挪动并给状态栏一句话）。

**索引页也能改了**（阶段 15）：「索引」那一页上双击格子能改**索引名 / 列 /
唯一**，工具栏上有「**+ 加索引**」「**− 删索引**」。索引的「列」用逗号分开
（如 `id, name`）；**MySQL 上 TEXT / BLOB 列建索引要写前缀长度**（`note(10)`），
不然数据库会报 `BLOB/TEXT column used in key specification without a key
length`；PG 不支持前缀索引，text 列直接写列名就行。**主键索引不在这一页**——
主键归「字段」页的「主键」列管。索引改动在 PG 上是几条独立语句，**包在一个
事务里**执行，中途失败会整体回滚（MySQL 的 DDL 不支持事务回滚，它是逐条原子
生效的）。

**外键页也能改了**（阶段 16）：「外键」那一页上双击格子能改**约束名 / 本表列 /
引用表 / 引用列**，工具栏上有「**+ 加外键**」「**− 删外键**」。新增外键时把
四栏填全（引用表和引用列要跟被引用的表对得上）。**只改约束名不会动引用关系**；
改了引用列或引用表则是「删了重建」。PG 上改名是 `RENAME CONSTRAINT`（一步），
MySQL 没有改名的语法，只能删了重建。

字段表里「可空」「主键」两列填「是」或「否」就行（也认 Y/N）。**默认值**填的是
表达式原文（`now()`、`'abc'`、`0`）。类型按各家的写法填（PG 写 `integer`、
MySQL 写 `int` 都行）。
结果表工具栏有一个「**导出…**」按钮，点开选格式（阶段 21）：**CSV**（Excel
友好，带 BOM）、**INSERT SQL 脚本**（值按列类型转义：数字不带引号、布尔写
TRUE、文本按方言转义，导出的脚本能在别处回灌）、**JSON**（一个数组，每行
一个对象，键是列名）、**XML**、**HTML 表格**（能直接在浏览器里看）。

⚠️ **NULL 和空串是两回事**：CSV 里 NULL 写成文本 `NULL`，而 JSON 里是
`null`、XML 里是空元素、HTML 里是空单元格。JSON / XML / HTML 里的特殊
字符（引号、反斜杠、`<`、`&`）也都转义过了，拿到文件直接能解析。

**列显示设置**（阶段 17）：结果页签工具栏上有一颗「列显示设置」图标（对标
Navicat 的字段显示设置），点开左边是所有列的清单，右边可以勾「显示这一列」、
「上移 / 下移」调顺序，另有「全显示 / 全隐藏」。表浏览页签和普通 SQL 查询页签
都能用。**藏列只影响显示**：待保存的改动和导出的 INSERT SQL 仍按全部列算——
藏一列不该让那一列的数据从语句里消失。

**列显示设置会记住**（阶段 20）：在**表浏览**页签里挑好要显示的列、排好顺序，
**下次打开这张表还是这个样子**（存进 `~/.config/puttyplus/columns.ini`）。
设置是**按连接 + 表**分开存的：同一个 SSH 会话下挂多个数据库连接不会串味，
换一个库就是另一份设置。普通 SQL 查询结果不记（每次查出来的列都不一样，
记了也没意义）。表以后**加了新列**，新列会出现在末尾并且是显示着的——
不会被悄悄藏起来。

**导入 CSV**（阶段 18）：对象树里右键一张表 →「**导入数据（CSV）…**」
（Navicat 的 Import Wizard）。选好文件后会弹出**字段映射**界面：左边是表的
列（带类型），右边下拉选这一列对应 CSV 的哪一列——**默认按列名自动配好**
（忽略大小写、下划线和空格，Excel 里手打的 `User ID` 能对上数据库的
`user_id`），配错了可以自己改；上面还能改**分隔符**（逗号 / 制表符 / 分号）、
**首行是不是列名**、**空字段算不算 NULL**，下面有前 3 行预览给你核对。

导入是**整批一个事务**：要么都进、要么都不进。中途出错（比如值重复了）会
**全部回滚**，数据库里一行都不会留下，弹窗里会告诉你「已全部回滚」和具体是
第几行、什么原因（重复值、不能为空、外键对不上……都翻译成中文，原文也留着）。

**ER 图**（阶段 19）：对象树里右键一张表 →「**ER 图…**」（Navicat 的
Database Model），把这张表跟外键相关的表画成一张**关系图**：被引用的表在
**左边**，引用它的表在**右边**，外键画成一条**箭头指向被引用表**的线，线的
端点正好落在**具体那一列**上（多列的外键不会挤成一团）。表框里列名、类型、
`PK` / `FK` 标记都标着。**可以拖动表框**挪位置，**双击表框**直接打开这张表
的数据页签，工具栏还能「重新布局」「放大 / 缩小」。右键**模式**则是画整个
模式的关系图。图是**只读**的——要改结构还是用表设计器（两处都能改会打架）。

对象树右键还有「**对象属性…**」（对标 Navicat 的 Details 面板）：弹一个
「属性 | 值」两列的窗口，看这张表/视图的**行数（估算）**、占用空间、列数、
索引数、外键数、类型、排序规则 / 字符集、创建时间、自增当前值、注释。
**取不到的项一律显示「—」，不编**：PG 没有创建时间、也没有「自增」这个概念，
MySQL 才有字符集和自增当前值。行数是估算值（PG 取 `reltuples`、MySQL 取
`TABLE_ROWS`），所以标题里写明「行数（估算）」——要精确行数得自己
`COUNT(*)`。PG 和 MySQL 两边的**列序是一样的**，换库不用重新学。

结果表工具栏还有「**插入行**」「**删除行**」（Navicat 同款）：点一下自动进入
编辑模式（开事务），末尾多一行空白新记录；**没填过的列不会出现在 INSERT 语句
里**，交给数据库用默认值（自增 id、`created_at DEFAULT now()`）。删除是"标记"——
这一行立刻从网格里消失，但要等点「保存修改」才真删，点「放弃」能恢复。三类改动
（插入 / 修改 / 删除）都排在**同一个事务**里，语句顺序是 INSERT → UPDATE →
DELETE，**任何一条失败就整体回滚**。提交成功后会自动重新查一次表刷新——插入行
的自增 id 和默认值只有数据库知道。

模式下面除了表和视图，还有**函数 / 存储过程 / 触发器**（展开模式时一次查齐，
三类各占独立的懒加载槽位——某一类失败只重查那一类）。双击它们会开一个
**定义页签**：里面是带 SQL 高亮、可以直接改的定义文本，底部有「复制定义」
和「执行定义」。执行定义是**逐条发完整语句**（不是拼成一条多语句）——
函数体里全是 `;`，客户端按分号拆会把体拆坏；PG 的例程本身是
`CREATE OR REPLACE`（幂等），触发器和 MySQL 的例程会先 `DROP … IF EXISTS`，
MySQL `SHOW CREATE` 带出来的 `DEFINER=xxx@yyy` 会在执行前去掉（换身份执行
会因为缺 SUPER 权限失败）。

还有**定时事件（Event）**，挂在**库（= schema）**节点下与表平铺。**定时事件只有
MySQL 有**（Event Scheduler）。PostgreSQL 压根没有这个功能——它有的是
`pg_event_trigger`（`CREATE EVENT TRIGGER`），那是 **DDL 钩子**，在 DDL 执行前后
触发一个函数，跟「cron 定时任务」名字像、性质完全不同；定时任务在 PG 上得靠
`pg_cron` 之类的扩展。所以 PG 侧不查事件：树上不会出现事件节点，**也不会报
「读元数据失败」**。MySQL 的事件元数据只查跨版本稳定的列
（`INTERVAL_VALUE` / `INTERVAL_FIELD` / `STATUS`），节点说明列写成
「事件 · 1 DAY · ENABLED」，调度保留原文不翻译。双击事件同样是定义页签，执行时
先 `DROP EVENT IF EXISTS` 再 `CREATE`。

**数据库连接也在会话树里**（Navicat 的连接树）：一个 SSH 连接下面可以挂
**多条**数据库连接，配置存 `databases.ini` 的子组 `[<会话键>/<连接名>]`，
连接之间靠**连接名**区分（老格式的 ini 照样能读，保存时自动迁移）。侧边栏
会话树里这些连接挂在所属 SSH 连接**下面**（数据库通道是复用这条 SSH 连接
的 `direct-tcpip` 转发，天然属于它），双击打开数据库窗口并预填该连接
（**不自动连接**），右键可以「删除这个数据库连接」（二次确认，只删那一条）。
连接表单里的「连接名」留空会自动生成 `pg 127.0.0.1:5432/postgres`，而且
**地址或类型变了名字会跟着重算**（只有自动生成的那种才跟，用户手动改过
的不动）——名字是 ini 里的主键，不跟的话把 PG 改成 MySQL 却忘了改名，保存时
会按同名写入、把原来那条 PG 连接覆盖掉。

结果表工具栏是**纯图标按钮**（Adwaita symbolic + 悬停提示：过滤条件 / 列显示设置 /
下一页 / 导出 / 编辑 / 插入行 / 删除行 / 保存修改 / 放弃，筛选框带放大镜），
一排八颗文字按钮在 940px 宽的窗口里右侧会被切掉。导出是**一个**按钮，
点开菜单选格式（CSV / INSERT SQL / JSON / XML / HTML）。

工具栏上的**漏斗图标**是**过滤条件编辑器**：一行一个条件
`[列] [并且/或者] [操作符] [值]`，操作符有 `=` `<>` `>` `>=` `<` `<=` `LIKE`
`NOT LIKE` `IN` `IS NULL` `IS NOT NULL`。它是**服务端过滤**——条件拼进 WHERE
重新查库（本地筛选只能筛已经取回的 200 行，表达不了 `id > 100 AND name
LIKE …`）。值的转义跟写库用同一套：整数列填 `abc` 在本地就报中文原因，不生成
会被服务器骂的 SQL；列名一律按方言转义。

对象树的右键菜单里还有**新建表 / 重命名 / 删除表 / 刷新**：新建表填「表名 +
列定义（每行「名称 类型」）」，改名按方言分派（PG `ALTER TABLE … RENAME TO …`，
MySQL `RENAME TABLE … TO …`），**删表必须二次确认**。DDL 成功后只刷新那个
模式节点——整树刷新会把用户展开的层级全收起来。

对象树这边有三个 GTK4 的坑，实现上绕过去了（症状都是"连上了但树里什么都没
有"，很容易误判成数据库连不上）：

- **TreeView 的列要显式绑 `text` 属性**。GTK4 的 `pack_start()` 只把渲染器
  塞进列，不会把某一列的模型值喂给它；不补一句
  `add_attribute(renderer, "text", col)`，单元格就是一片空白——**列头还在**，
  看着像"查出来是空的"。本项目的文件列表树一直是这么写的，新写的对象树和
  结果表一开始漏了。
- **没有子节点的行，`expand_row()` 是静默无效的**（不发 `row-expanded`，
  也不画展开箭头）。懒加载是"展开才查"，根节点刚建好时没有孩子，于是第一
  层永远等不到触发。办法是给可展开的节点先挂一个「载入中…」**占位子节点**，
  真数据回来再摘掉；摘掉占位后还得**把父行重新展开**（摘占位会让 GTK 认为
  这一行没孩子从而折叠它，而折叠状态下展开子行同样无效）。
- **展开箭头和缩进画在第一列**，树里越深的节点留给文字的宽度越少。所以对象
  树只显示「名称 / 说明」两列，类型信息（"表" / "视图" / "模式" /
  "函数 → integer" / "BEFORE/INSERT · 表名"）并进「说明」列——单留一列「类」
  的话，在第二级缩进下那两三个字就只剩 "…"。

**深遍历 GtkTreeStore 不能用 `iter_next`**：在子行上调 `iter_children` 会让
**上层**的 iter 失效，递归两层后顶层 `iter_next` 直接返回 false，树只走了
一半（测试钩子当时一直报"树上没挂出数据库连接"，差点当成真 bug 去改树）。
可靠写法是**按路径走**：`TreePath::from_indices` + `append_index` +
`store.iter(path)`，每一步都从根重新定位，不依赖"当前位置"。


文件面板（本地与远程）右键有「打开」：内置纯文本编辑器（可改可存），
远端文件直接经当前 SFTP 连接读写，不用先下载。`Ctrl+S` 保存、`F5` 重新载入；
本地与远端保存都先写同目录临时文件再 rename。只处理 UTF-8 文本、单文件上限
8 MB；二进制文件拒绝打开，非法 UTF-8 只读预览不能保存。双击文件同样是打开
编辑器（阶段 23 起不再是下载/上传）。

编辑器带**行号**与**语法高亮**：左边一栏行号（当前行用强调色），按扩展名
（或首行 shebang）认出语言后给关键字/字符串/注释/数字等分色，支持 Rust、
C/C++、Java、Go、JavaScript/TypeScript、Python、Shell、JSON、YAML、TOML、
INI、Markdown、HTML/XML、CSS、SQL、Makefile、日志与 diff 共 20 多种。
状态栏右下角显示光标行列，右下角状态栏显示当前语言。

行号栏跟正文**连成一片**：不画分隔线、不留缝、也不带自己的滚动条（整屏
只有正文右边那一根），跟 Zed / gedit / VS Code 的观感一致。实现上踩过三个
GTK4 的坑，记在这儿省得再踩：

- **行号栏的滚动条策略用 `PolicyType::External`**。`Automatic` 会长出一根
  15px 竖条夹在行号和正文中间；`Never` 更糟——GTK4 认为"内容不能靠滚动条
  看到"，ScrolledWindow 的最小高度就变成行号文本的整段高度，长文件直接把
  窗口撑到几万像素高，X 报 `BadAlloc`；`External` 既不显示也不占位置，而
  adjustment 照常工作（行号栏靠它跟正文同步）。
- **行号后的"影子字符"要画成底色，不能靠 alpha 透明**。GTK4 **不吃前景色
  的 alpha**：实测单独给一段字挂 `foreground_rgba(alpha=0)`，字照样画出来。
  以前影子看着"隐形"，其实是被行号栏的窄宽度裁掉了；一旦滚动条位置变了，
  那些汉字就浮了出来。改成画成行号栏底色（同色即隐形）才真的稳。
- **同一段文字上别挂两个抢前景色的 tag**。GTK4 里两个 tag 抢同一个属性时谁
  赢并不按文档的"优先级高的赢"来（实测换了顺序也一样）。所以改成"挂新的
  先摘旧的"，同一位置永远只有一个 tag，也就不用去赌它的裁决规则。

高亮是**自己实现的词法高亮**，没有引入 GtkSourceView：GTK4 对应的是
gtksourceview-5，本机发行版只打包了 GTK3 时代的 gtksourceview-3/4，用它
就得给每台堡垒机源码编译一个系统库、deb 包也得跟着加依赖。现在是零新依赖，
单二进制与 deb 包都不用动。代价是只做词法级着色、不做语法分析，且超过
1 MB 的文件不高亮（状态栏会说明）。

实现上有个 GTK4 的坑值得记一笔：**`GtkTextTag` 的名字必须一类一个**。
GTK 的 tag 表按名字索引，同名的 tag 只有第一个进得去，后面的会被直接拒收
（`A tag named '…' is already in the tag table`），而 `apply_tag` 又要求 tag
属于本 buffer 的表——被拒的那些一个都上不去，结果就是「状态栏写着高亮、
满屏却一点颜色都没有」。另外 tag 的优先级必须在**进表之后**设、且要小于
表里的 tag 数（`set_priority` 有这两条硬性要求）。

本地面板会记住上次的目录：每次进入目录/上级/主目录或手输路径都会写进
`settings.ini`，下次启动自动恢复；关主窗前再记一次当前标签的目录。记忆的

本地/远程文件列表会自动跟随外部变化：本地面板用 GIO 目录监视，命令行或外部程序
增删/改名后约 250ms 刷新；远程面板每 2.5 秒 stat 一次当前目录 mtime，变了才静默

文件面板支持多选后右键「上传… / 下载…」：选中的文件和目录一次全部入队。

⚠️ **阶段 100 的根因分析（重要，别再走偏）**：

1. **应用侧的真 bug**：`gtk::DropTarget`（同步版）在「拖拽进入」时把
   `GdkDrop` 存进 `self->drop`，而它读数据是**异步**的
   （`gtk_drop_target_load()` → `gdk_drop_read_value_async`）。只要这次读
   **没回调**（源端不应答 / 用户中途松手），`self->dropping` 永远 TRUE、
   `self->drop` 永远留着旧 drop ⇒ GTK 下一次拖拽进入时
   `if (self->drop != NULL) return;` ⇒ **这个控件上此后所有拖拽全部失灵**
   （症状：每个 motion 都报
   `gtk_drop_target_handle_event: assertion 'self->drop == drop' failed`，
   事件被丢弃）。⇒ **一次没落下的拖拽会毒死后面所有的拖拽**——这才是
   「拖拽上传完全没作用」的主因。改用 `gtk::DropTargetAsync`（它在拖拽
   **离开**时清 `self->drop`，且没有 `dropping` 这个中间状态）。
2. **应用侧的第二处**：同步版只认 GType，而同进程内「只给 mime 的源」与
   「要 GType 的目标」匹配不上 ⇒ **远程列表 → 本地列表的下载拖拽从来没
   协商成功过**。现在自己按 mime 判定接不接、自己选读取类型。
3. **读数据加了 5 秒超时**：GTK 的选区输入流**没有超时**，源端不应答时会
   永远挂着（用户看到的现象和"拖拽根本没触发"一模一样）。超时要**明确说
   出来**（「没拿到文件数据，请改用「上传…」」），不能一声不响。

⚠️ **阶段 101：把「源侧限制」的结论推翻了（这才是真根因）**

阶段 100 断定「Deepin 文件管理器声明了 XDND 类型却从不提供数据」——**错了**。
它**是肯给的**，只是**挑问法**。深挖三层（每层都有源码/实验佐证）：

1. **GTK3 为什么行（xterminal 就是 GTK3）**：`gtk/gtkdnd.c` 的
   `gtk_drag_get_data()` 用的是**拖放事件的时间戳** ——
   `gtk_selection_convert (ipc_widget, "XdndSelection", target, time_)`，
   `time_` 来自 "drag-drop" 信号（= XdndDrop 事件的时间戳）。
2. **GTK4 为什么不行**：`gdk/x11/gdkdrop-x11.c` 的 `gdk_x11_drop_read_async()`
   → `gdk_x11_selection_input_stream_new_async (…, CurrentTime, …)` →
   `gdk/x11/gdkselectioninputstream-x11.c`：
   `XConvertSelection (…, GDK_X11_DISPLAY (display)->leader_window, CurrentTime)`
   —— **请求方是 GDK 的隐藏 leader 窗口**（没有 `XdndAware` 属性）、
   **时间戳是 `CurrentTime`**（不是 XdndDrop 的那个）。
3. **源端为什么不给**：Qt5 的 `QXcbDrag::handleSelectionRequest()` 要把请求
   **对上号**才肯供数：
   - `event->time == source_time`（拖拽中的时间戳），或
   - `findTransactionByTime (event->time)`（XdndDrop 那个时间戳），或
   - `findTransactionByWindow (event->requestor)`（请求方就是落点窗口），或
   - `findXdndAwareParent (…, event->requestor)` 能上溯到带 `XdndAware` 的
     窗口，且 `current_target == 那个窗口`。
   ⇒ GDK4 那条路**四条全落空** ⇒ 源端回 `SelectionNotify` 且
   `property = None` ⇒ **不供数**。

**实测（/tmp/xdndtarget，自建 XDND 目标端收 XdndDrop）**：

| 请求方窗口 | 时间戳 | 结果 |
|---|---|---|
| 带 `XdndAware` 的窗口 | `CurrentTime` | ✅ 拿到 `file:///tmp/pp_dnd/DFM_drag_me.txt` |
| 带 `XdndAware` 的窗口 | XdndDrop 时间戳 | ✅ 同上 |
| 不带 `XdndAware` 的窗口 | XdndDrop 时间戳 | ✅ 同上 |
| 不带 `XdndAware` 的窗口 | `CurrentTime` | ❌ `property=None` |

⇒ **只要「请求方 = 收到拖放的那个窗口」，`CurrentTime` 就够用**（不需要
XdndDrop 的时间戳 —— GDK4 根本不把它暴露给应用）。

**修法**（新模块 `src/panel/xdnd11.rs`）：在 drop 回调里自己发一次
`XConvertSelection`：
- 请求方 = **顶层窗口的 XID**（`gdk_x11_surface_get_xid`；GDK4 把 `XdndAware`
  挂在顶层 surface 上，见 `gdk/x11/gdksurface-x11.c` 的
  `_gdk_x11_surface_register_dnd()`）⇒ 命中 Qt 的 `findXdndAwareParent` 分支；
- 时间戳 = `CurrentTime`；
- 源端把数据写进**请求方窗口的属性**里，我们**轮询属性**拿数据 ——
  **不接 `SelectionNotify` 事件**（那个事件 GDK 会先读走；读属性更稳）；
- 只在 X11 后端生效（display 名字是 `:0` 才做；Wayland 走 GDK 原生通道）；
- 读不出来就返回 `None`，**照旧走 GDK 的读法**（同进程拖拽、GTK4 源端走那条），
  行为不倒退。

⚠️ **别再重复阶段 100 那个错误结论**：不是「源端不提供数据」，是
**「问法不对」**。改动前先读 `src/panel/xdnd11.rs` 的模块说明。


**设置都收进「首选项」一个窗口**（阶段 69，审计 P1-4）：以前设置项散在**四个
地方**——「外观」窗口、标签上的「会话选项…」、连接编辑器、传输队列窗口顶部，
再加列设置、窗口尺寸、侧栏宽度各在自己入口 ⇒ 用户想调一个设置得先知道它
在哪。现在是**一个窗口六个页**（外观 / 终端 / 传输 / 安全 / 快捷键 / 高级），
入口在「工具 → 首选项…」（原「视图 → 外观…」进的是**外观页**）。每个设置项
**有且只有一个归属页**（注册表 `SETTINGS` 是唯一真相）。传输设置从队列窗口
顶部搬走，那里只留**只读摘要 + 「去设置」链接**。终端配色归「终端」页，并
新增**全局终端字号**（以前终端字号只有"连接里设的"和"会话覆盖的"两档、没有
全局默认 ⇒ 想把终端字体调大得逐条连接去改；优先级：**连接 > 全局默认 >
内置 10.5**）。

**连接编辑器的「会话」页**（阶段 69 之二）：会话相关的五个设置——保活间隔、
终端类型（TERM）、认证优先级、终端字号、响铃——以前**只有一处**能改：标签上
的「会话选项…」，而那是**运行时临时覆盖**（存 `settings.ini` 的会话段），
用户想给某条连接**固定**一套会话设置（堡垒机固定认证顺序、跳板机固定保活）
根本没有地方填。现在连接编辑器分**三个页签**（常规 / 认证 / 会话），「会话」页
存的是**这条连接的默认值**（存 `connections.ini` 的条目段，新键 `keepalive` /
`term` / `authorder` / `font` / `bell`；**缺键 = 内置默认**，等于默认值的键不落盘）。

三层优先级：**连接默认值 < 会话覆盖 < 内置默认**。「会话选项…」对话框改的
仍是**当前会话的临时覆盖**（优先于连接默认值），它预填的是**当前生效值**
（不是"覆盖里存了什么"）——连接里配了 12 号字、覆盖里没记，对话框就该显示
12 而不是空白。

**连接编辑器的「认证」页**（阶段 70，审计 P1-5）：连接编辑器现在是**三个页签**
（常规 / 认证 / 会话）。「认证」页给出**认证方式**——自动（按认证优先级依次
尝试，与以前一样）/ 只用 ssh-agent 里的密钥 / 只用指定的私钥文件 / 只用密码。
以前只能调「先试哪个」，不能限定「只准用哪个」⇒ 不想把本地身份出示给堡垒机
网关时做不到。页面上还有**私钥选择器**（列 `~/.ssh` 里的私钥，也能「浏览…」
挑别的路径）、用户名、密码，以及**「记住密码」**：凭据库**没启用或锁着**时
这个勾**不可用**——勾了也只是明文写进 `connections.ini`，用户以为「记住密码」
就是加密保存，正好了；状态行就地说明当前凭据库是什么状态。

认证方式只管**本程序自己的 SFTP 通道**；终端里跑的是 ssh 客户端，它按
`~/.ssh/config` 与命令行来。

**端口转发并成一张结构化表**（阶段 71，审计 P1-3）：连接编辑器现在是**四个页签**
（常规 / 认证 / 转发 / 会话）。「转发」页是一张表：`类型 | 监听 | 目标 | 机制 |
启用`——以前是两个长得一模一样的原始规则域（终端转发 / 进程内端口映射），
用户分不清哪条走哪套机制，也得自己拼 `L:[addr:]port:host:port` 这种字符串。
「监听」「目标」双击就改，「启用」点一下就切；类型与机制在「添加…/编辑…」
对话框里选（双击行也行）。

**存储格式一点没变**：`forwardings`（交给 spawn 出去的 ssh -L/-R/-D）与
`inprocess_forwardings`（跑在应用自己那条 SSH 连接上）两把键照旧 ⇒ PuTTY
互转与兼容基线都不受影响。原始规则域也没删，挪到表下面的折叠区里（粘贴
PuTTY 会话里的规则走这条路）。

**表数据导入/导出收成一个入口**（阶段 72a，审计 P1-7 / P1-8）：顶部入口改成
菜单按钮「表数据导入/导出…」，就两项——「导入数据（CSV）…」与「导出表…」——

「数据传输」这个词在 DB 这一侧退休了：SFTP 那边「传输」指的是**文件**上传
下载，DB 那边指的是**表数据**，两回事共用一个词用户根本分不清。

**两个「过滤」分清名字，列设置只留一个入口**（阶段 72b，审计 P1-7 / P2-10）：
结果页签顶部那个输入框现在叫「**筛选已加载行**」（在已经取回的行里按文字筛，
不查库），工具栏那颗漏斗按钮叫「**数据库过滤条件**」（生成 WHERE 重新查库）。
以前两个都叫「过滤」，点错了才发现不是一回事。

列设置原来有两个入口——列头的「⋮」菜单和工具栏上的「列显示设置」按钮；
现在工具栏那颗撤了，列设置只在列头菜单里（「列显示设置…」）。

**网格列宽按内容分配，结果页签标明能不能改**（阶段 72c，审计 P2-10）：
每列的宽度现在按内容实测，剩下的可用宽度按比例分给各列——以前右边留着

**按列名存** ⇒ 藏过列不错位）⇒ **重开页签宽度还在**。⚠️ 落盘**去抖 1.5 秒**
（网格每 100ms 比一次列宽）；⚠️ 「恢复默认宽度」会**把存的那份删掉**。

结果页签左上角多了一个标志：**只读**（普通查询结果 / 视图）或**可编辑**
（表浏览页签，绿色）。以前工具栏上「编辑 / 插入行 / 删除行」三颗按钮平时是
灰的，页面上却没有一处说明。

**自动展开默认模式**（PG 是 `public`，MySQL 是当前库）——以前只展开到模式这一

**打开一张表 = 打开一个「表文档」**（阶段 72e，审计 P1-7）：以前一张表有**五个
平级入口**——双击看数据、右键「表结构」看字段、右键「对象属性…」看属性、
右键「ER 图…」看关系、还有「查看定义」——它们在页签栏里长得一模一样，用户
分不清哪个是哪个的侧面。现在双击一张表就是**一个文档页**，页内四个视图页签：
**数据 / 结构 / 属性 / ER**。对象树右键「表结构」「对象属性…」「ER 图…」
（表级）都**切到同一个文档的对应视图**，不再另开平级页。

其余两个视图是**懒建**的：ER 图要查整个模式（几百张表），结构要查四份元数据，
一开表就全查一遍是白花钱——切到那一页时才真建。

⚠️ **这次顺手修了一个老坑**：结构视图最"重"（200px 的字段表 + 80px 的 DDL
预览，最小高度能到 506），而工作台的竖直分栏只分 320 给页签区 ⇒ `GtkPaned`
默认会把两边**挤到比各自最小高度还小**，结果**页签栏被挤成 0 高**——用户看到
的是"页签整个不见了"（外层页签和「数据/结构/属性/ER」都没了，网格直接顶到
顶上）。现在分栏**不许挤**，Paned 会自己把分隔条挪到合法位置。

⚠️ **函数 / 存储过程的「定义」没有并进来**（那是另一个对象，不是这张表的
侧面），仍是独立页；**模式级 ER 图**（整个模式）同理，也仍是独立页。

**说明文字的对比度达标**（阶段 73a，审计 P1-10）：默认主题是「跟随系统」，
而那套 CSS 里的次要文字色直接取了系统的**禁用色**（`insensitive_fg_color`，
Adwaita 浅色下约 `#8e8e8e`）⇒ 白底上只有 **3.03:1**，低于 WCAG AA 正文的
4.5:1。表单标签、欢迎页快捷键、空态副标题这些**要读的文字**全都偏淡。

现在次要文字色改成从正文色**往底色混**，混到对比度**还够 4.5:1** 为止
（实测「跟随系统」下从 2.77:1 提到 **4.91:1**），字号也从 10pt 提到 11pt。
对比度是自己按 WCAG 2.x 算的（GTK4 没有这个接口），单测四套主题 + 冒烟量
**真正交给 GTK 的那份 CSS**。

**对话框尺寸收敛 + 动作收敛**（阶段 73b，审计 P1-11）：

- **新建连接**：实测自然高度 **661px**（审计记的 810px——阶段 70/71 把它拆成
  四个页签后缓解了一截，但仍超 1366×768 的可用高度，底部按钮区直接出屏），
  而且没有滚动容器。现在页签套进**滚动容器**并限高 ⇒ 实测 **460×514**。
- **新建 / 编辑数据库连接**：实测自然宽度 **1030px**（审计记的 940px）——
  顶部那段说明 label 只 `wrap` 没限宽，而 `wrap` 是按**分配到的宽度**折行、
  父容器又默认按**自然宽**排版 ⇒ 永远不触发 ⇒ 把对话框撑到 1030px。现在
  说明 label 补上 `set_max_width_chars(60)`，表单套滚动容器限宽 ⇒ 实测
  **560×593**。
- **数据库连接表单里重复的「记住密码」标签删掉**（勾选框自带文案，同一行
  出现过两次「记住密码」）。
- **新建连接的四个动作收敛成「取消」+「连接」**，旁边一个**「保存到连接列表」
  勾选**（默认勾上 = 老对话框回车默认的「保存并连接」；不勾 = 仅连接、不留痕）。
  老对话框「取消 / 仅连接 / 保存 / 保存并连接」四个按钮并排，用户分不清
  「是否保存」「是否连接」的区别。⚠️ 代价是**「保存但不连接」这个出口没有了**
  （计划要求收敛成「连接」+ 勾选）。

**顶栏菜单补全**（阶段 74，审计 P1-13）：顶栏菜单以前**一个快捷键都不显示**
（用户只能去查「快捷键一览」），而且**没有会话时终端相关的项全是亮着的**
——欢迎页上打开「终端」菜单，「复制 / 粘贴 / 查找 / 分屏 / 关闭当前终端」
点了没反应。另外「显示侧边栏」是带勾的开关项，「按键广播（开关）」「记录
终端日志（开关）」「录制会话（开关）」却是普通项 ⇒ **同一类状态三种表现**。

现在菜单项右边**显示快捷键**（11 个窗口级快捷键全部露出来，和「快捷键一览」
是同一张表）；没有终端 / 会话时相关项**灰掉**（动作也一起禁用）；广播 / 日志 /
录制统一成**带勾的开关项**，文字里不再写「（开关）」。

**标签标题与窗口标题**（阶段 75，审计 P1-14）：标签头标题以前用
`width_chars(10)`，而 GTK4 里那是**固定请求宽度**（不是最小宽）⇒ 单标签、
满屏空白时标题也只显示 10 个字（`fwt@127.0...`），18 字的上限没机会生效。
顶栏那个标题标签更是固定写死 "PuTTYPlus"，多窗口 / 多会话时从窗口顶部
分不出是哪台机器。

现在标签头标题**宽度随内容变化**（上限 18 字、超出用省略号、显式最小宽
64px 保证不会被挤成「… ×」），顶栏标题**跟着当前标签走**（欢迎页显示
应用名）。

**文件面板列宽与状态行**（阶段 76，审计 P1-15）：340px 宽的文件列表里，
名称 / 大小 / 权限 / 修改时间 四列把文件名挤得只剩约 120px，长文件名还被
**硬裁**（看不出后面还有字）；大小和时间列左对齐；远程状态行又把**完整
路径重复一遍**（路径栏已经有一份），窄面板里直接截断。

现在名称列下限提到 **160px**（340px 面板里实测 175px），超宽时画**省略
号**（列表行 tooltip 里能看完整名字 + 大小 + 修改时间），「修改时间」列
默认藏起来，大小列**右对齐**，状态行只留「已连接 host」（路径进 tooltip）。

## 与 C 版的差异（有意为之）

- **依赖更少的安全实现**：SSH/SFTP 从 libssh（C 库）换成纯 Rust 的
  russh + russh-sftp；known_hosts 校验为自实现（支持 hashed /
  `[host]:port` / `@revoked` / accept-new），行为与
  `StrictHostKeyChecking=accept-new` 一致，回环地址仍免校验。
- **连接管理器 spawn 新窗口时密码不再放进 argv**（`ps aux` 可见），
  改用 `PUTTYPLUS_PW_SESSION` 环境变量传递（仅同用户可读）。
- **递归传输/删除增加 32 层深度上限**（C 版无界递归）。
- 后台任务从 C 版的 `memcpy` 打包 + 函数指针 job 队列换成 enum 消息
  channel（`panel/worker.rs`），连接对象由 worker 线程独占持有。
- UI 升级到 GTK4：右键菜单改 PopoverMenu，对话框改异步回调；
  TreeView/ListStore 沿用（GTK 4.10 起官方推荐 ListView，功能等价）。

## 与 C 版的外部行为兼容性

`rust/tools/compat_check.sh` 做三层自动对比（共 80 项，当前全部通过）：

1. **CLI 矩阵**（74 项）：全部 PuTTY 参数逐项比对 `--print-config` 的
   stdout / stderr / 退出码——协议开关、忽略项、值参数（含 `-P` 溢出/非法/
   负数的 atoi 语义）、`-title`/`-title=`、`--`、未知参数不吞值、缺值告警、
   `-pwfile`/`-m` 文件、PuTTY 会话（位置参数与 `-load` 两种形态及 host 覆盖）、
   `~/.ssh/config` 别名解析、`SSHPASS` 兜底与优先级。
2. **特殊分支**：askpass 显式调用（stdout 逐字节一致）、`--sftp-selftest`
   用法错误（退出码 2）、非法端口（atoi 得 0，错误文案经
   `setlocale`+`strerror` 与 C 版同源，如中文“拒绝连接”）。
3. **spawn 沙箱**（5 组）：用假 ssh/plink 捕获 GUI 实际拉起子进程的 argv 与
   环境变量（TERM/COLORTERM/SSH_ASKPASS/SSH_ASKPASS_REQUIRE/PUTTYPLUS_PW/
   DISPLAY）——含参数全家桶、带密码的 askpass 环境、密钥+密码不设 askpass、
   plink 的 `-P`/`-pw` 形态。

已知的展示层差异（不影响对接与自动化）：

- SSH 协议层内部错误（握手/密钥交换等）的措辞来自各自库（libssh vs russh），
  网络层 errno 文案已同源对齐；
- 无参数启动时 GTK4 会在 stderr 多打一行
  `Gtk-Message: GtkDialog mapped without a transient parent`（GTK3 无此提示）。

堡垒机场景（askpass 自动应答、PTY 屏幕扫描、OSC 7 / /proc 目录跟随）
与 C 版一致，详见主 README。
