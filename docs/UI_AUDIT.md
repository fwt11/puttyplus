# PuTTYPlus（Rust 版）UI/UX 审视报告

> 范围：`rust/src/` 全部界面层——主窗、侧边栏、标签栏、欢迎页、SFTP 双栏、
> 终端与状态条，以及 14 个对话框/独立窗口（连接管理、编辑连接、手动连接、
> 私钥管理器、外观、会话选项、传输队列、端口转发、目录镜像、快速命令、
> 凭据库/主密码、录制回放、关于、快捷键一览、传输汇总）。
> 依据：用户提供的 4 张截图 + 逐文件读代码（引用格式 `文件:行`）。
> 截图可能来自较早构建：文中"截图可见"与"代码可见"分开标注。
>
> **2026-10-18 更新**：P0 已落地，见文末 §7；§1–§3 保留的是改动前的状态。

## 0. 结论摘要

**一句话**：功能密度很高、文案很诚实，但**没有视觉系统**——颜色靠散落的
硬编码、层级靠加粗、分组靠空行、图标靠 emoji、动作靠右键。所以"丑"不是
配色选错了，是**缺少一套贯穿全部界面的设计语言与组件规格**。

| 维度 | 评分 | 主要问题 |
|---|---|---|
| 信息架构 | 2/5 | 同一功能 3 个入口；地址信息只藏在 tooltip；工具栏 10 个图标挤一行 |
| 视觉层级 | 2/5 | 段落加粗当标题；主次按钮同等权重；选中态把说明文字压成灰字 |
| 一致性 | 2/5 | 4 套间距、5 种图标风格、3 种按钮形态、8 处硬编码状态色 |
| 可发现性 | 2/5 | 文件操作只在右键；关标签无 ×；无菜单栏；长提示当说明书 |
| 可访问性 | 2/5 | 选中行 dim 文字对比不足；图标按钮无文字；纯 placeholder 当标签 |
| 密度/效率 | 3/5 | 已有紧凑模式，但只作用于主窗，对话框不吃 |

**最该先修的 5 件事**（都便宜、都是"一眼丑/一眼错"）：
1. 私钥管理器提示里的**字面量 `\n`** 把窗口撑到 1712px（`keyui.rs:29`，无 `set_wrap`）；
2. 会话选项对话框**标签与控件错位** + 提示文字**压在控件上**（`sessopt.rs:86`）；
3. 主题的 `.dim-label` 在**选中行**上对比度崩掉（`theme.rs:285`，截图 3 即证据）；
4. 状态色/失败色**硬编码 hex**，切明暗/高对比后不跟随（`panel/mod.rs:223` 等 7 处 + `queue.rs:265`）；
5. 成功提示也用**错误对话框**（"已生成""转换完成""已导入"），信息语气错位。

## 2. 系统性问题（跨界面，优先级最高）

### S1. 没有设计令牌：颜色散落在三处，且互不知情

现状：
- **主题层**用 `@define-color` 定义 8 个变量（`theme.rs:232-286`），但只覆盖
  GTK 控件基础样式；
- **业务层硬编码语义色**：`#2ecc71` 已连接、`#f39c12` 连接中、`#e74c3c` 失败
  （`panel/mod.rs:223/229/341/430/434/439/794`、`queue.rs:265`）；
- **Markup 里写死前景色**：`format!("<span foreground='{color}'>●</span> …")`
  （`panel/mod.rs:301`）——CSS 变量对它无效，切主题时状态点永远是同一批色。

后果：高对比主题下 `#2ecc71` 绿点压纯黑、`#e74c3c` 红字压浅底，对比度不达标
（`#e74c3c` 压白底约 3.8:1，低于 4.5:1）；暗色主题下这些色偏亮，与整体不协调。

**建议**：把语义色迁移成 CSS 类 + 每主题一份定义，状态色改为
`Label` + `.pp-ok/.pp-warn/.pp-err` 类（`queue.rs` 的 `CellRendererText`
前景色需要按当前主题取 `RGBA`，见 §6 实施注记）。

### S2. 没有间距/字号刻度：127 处手写 margin，值有 2/3/4/6/8/10/12/18

`grep -c margin_*` = 127。对话框内边距出现 8/10/12/18 四种；列表行上下
3/6/12 三种（`keyui.rs:248`、`fwdmgr.rs:157`、`themeui.rs:189`）。
视觉上表现为"每个窗口都像不同人拼的"。

**建议**：4 的倍数刻度（4/8/12/16/24），用 CSS 类
`.pp-dialog`/`.pp-section`/`.pp-row` 统一，不在业务代码里堆 `set_margin`。

### S3. 图标体系是混搭的：symbolic、全彩、emoji、字符画四种并存

| 类型 | 例子 | 位置 |
|---|---|---|
| symbolic 图标 | `view-refresh-symbolic` | 工具栏/侧边栏 |
| 全彩图标主题 | `folder` / `text-x-generic` | SFTP 列表（`pane.rs:191`） |
| emoji | `⬆ 上传` `⬇ 下载` `＋ 建目录` `▶ 播放` `⏮ 重播` `⌨` | `queue.rs:190-197`、`replayui.rs:361-408`、`term.rs:364` |
| 字符画 | `✓` / `·`（列显隐）、`⤷`（广播/日志）、`●`（录制/状态点） | `pane.rs:568`、`term.rs:566/831`、`mod.rs:302` |

同一个动作还出现**两个图标**：`preferences-system-symbolic` 既是"连接管理"
（`sidebar.rs:163`）又是"会话选项"（`pane.rs:339`）；
`applications-graphics-symbolic` 表示"外观"（`sidebar.rs:174`），语义是"图形"。
ssh config 条目用 `text-x-generic-symbolic`（`sidebar.rs:259`）——看起来像文件，
不像机器。

**建议**：固定一套 symbolic 图标 + 16px 尺寸；emoji 全部替换为
"图标 + 文字"按钮；建立图标-语义对照表（附录 B），一个动作只用一个图标。

### S4. 长提示当说明书：对话框顶部塞 2~4 行说明，且不换行

- `keyui.rs:29-33`：提示用 `\\n`（Rust 里是**字面量反斜杠 n**）且未
  `set_wrap(true)` → 截图 1 中窗口被撑到 1712px，正文里肉眼可见 `\n`；
- `fwdmgr.rs:61-66`：三段说明无 `set_wrap`；
- `sessopt.rs:101-108`：提示用 `gtk::attach` 到第 3 行，**与"认证优先级"控件重叠**；
- `quickcmd.rs:316-324`：`set_markup` 三行说明，`${...}` 在 Pango 里是安全的，
  但文字量仍过大。

**建议**：每个对话框顶部**最多一行**说明，长解释进 tooltip / 帮助按钮；
所有说明 `set_wrap(true)` + `set_max_width_chars(60)`。

### S5. 动作层级扁平：一行 8~10 个同等权重按钮

- 连接管理：新建/编辑/删除/凭据库/私钥/导入 PuTTY/导出 PuTTY/手动连接/连接
  **9 个按钮一行**（`connmgr.rs:1088-1111`）；"连接"是唯一 `suggested-action`，
  但被挤在最右端、与"手动连接"相邻。
- 远程面板：状态文字 + 重连/队列/镜像/转发/会话选项/快速命令/跟随 + 分隔 +
  主页/刷新/隐藏 = **10 个平铺控件**（`pane.rs:298-399`）。
- 队列：取消/清除/断点续传/校验 = 2 按钮 + 2 复选混排（`queue.rs:56-99`）。

**建议**：按钮分三档——主按钮（1 个，实底）、次按钮（描边）、图标按钮
（flat，成组 + 分隔线）；超过 3 个工具动作收进"⋯"溢出菜单。连接管理把
CRUD 留一行，凭据库/私钥/导入导出收进"更多"。

### S6. 对话框是"默认 GTK 拼装件"，没有统一骨架

十几个对话框几乎全是 `gtk::Dialog` + `Grid`：标签右对齐、输入框占满、底部按钮
系统自动排；标题栏有 ×，底部又有"关闭"按钮（**双重关闭**）；
`AlertDialog` 的 `message` 被当成标题用（`vaultui.rs:166`、`keyui.rs:130`），
于是"已生成"这种小提示也变成一条醒目的告警条。

**建议**：统一三段式（说明区 → 表单区 → 右对齐底栏），标签**顶对齐**放在
输入框上方；成功提示改用轻量 toast/状态条，不再借用 AlertDialog。

### S7. 危险操作没有确认，安全操作却要二次确认（不对称）

- **删除连接条目无任何确认**（`connmgr.rs:1295-1314`，直接 `delete_entry`）；
- 删除远端文件有确认（`panel/mod.rs:726-773`）；
- 关闭标签无 × 也无确认（`tabs.rs`，只能 `Ctrl+Shift+W`）。

### S8. 每个窗口尺寸写死、不记忆

`main.rs:113` 1200×780、侧边栏固定 230px（`main.rs:123`）、
`keyui` 620×440、`connmgr` 560×400、`mirrorui` 860×560、`queue` 720×320、
`replayui` 900×600…… 全部 `set_default_size`，**没有任何窗口几何持久化**
（`settings.rs` 里只有 `sftp_pane_pos`）。用户每次启动都要重新拉一次窗口和
分栏——这是桌面工具最高频的抱怨点之一。

### S9. 紧凑模式只作用于主窗，对话框不一致

`density.rs:164-166` 只 `set_window(主窗)`，`apply_density` 给这一个窗口加
`.pp-compact`（`density.rs:194-204`）。结果是：主界面收紧、点开的对话框仍是
宽松版，视觉断层。

## 3. 逐界面问题

### 3.1 主窗整体（截图 4）

1. **没有菜单栏、没有 header bar 动作区**：窗口只有标题 + 最小化/最大化/关闭。
   所有能力分散在"侧边栏底部 4 个图标 + 面板工具栏 10 个图标 + 右键菜单"。
   来自 PuTTY 的用户找不到"新建会话/保存会话/导入"。
2. **没有全局状态区**：连接状态写在远程面板第一行，长文本被省略号截断
   （`pane.rs:299-303`）；窗口底部空白，没有状态栏。
3. **区域之间没有视觉边界**：侧边栏 | SFTP | 终端 三段靠 Paned 分隔线，
   终端是纯黑大块，没有内边距/描边，看起来"没有做完"。
4. **两个 Paned 手柄没有提示**：用户不知道 SFTP/终端、远程/本地可以拖。

### 3.2 侧边栏（截图 4）

1. 分组标题（最近/自定义/ssh config）与条目**同样字号、同样图标列**，层级靠
   缩进和粗体——扫读时找不到"段落在哪"。
2. 条目只有名称，**地址只在 tooltip 里**（`sidebar.rs:254-258` 设
   `COL_TIP`）。用户无法一眼确认"这条连的是哪台机"。
   （截图 4 的侧边栏似乎把地址拼进了行文字，与当前 `sidebar.rs` 不一致——
   以代码为准：地址目前只能悬停看到。）
3. 底部 4 个图标各占 1/4 宽（`set_hexpand(true)`），语义混杂：
   刷新 / 连接管理 / 外观 / 关于——把"刷新列表"和"关于"放同一排。
4. 过滤框紧贴标题，没有清空按钮、没有结果计数。

### 3.3 标签栏（截图 4）

1. **没有关闭按钮**，也没有右键菜单；关标签必须记快捷键（`tabs.rs:59-93`）。
2. 标签宽度固定 16 字符（`tabs.rs:139`），两个标签就吃掉半条栏；
   没有中间省略、没有数量溢出策略。
3. 标签上**没有连接状态**（在线/断开/有失败传输），多个同名标签无法区分。
4. 侧边栏开关与"+"是 notebook 的 action widget，视觉上像标签的一部分
   （`main.rs:140-150`、`tabs.rs:78-89`），位置在标签条两端——易误点。

### 3.4 欢迎页（截图 4）

只有三行居中文字（`tabs.rs:499-528`）：标题、副标题、一行快捷键。
没有 logo、没有主行动按钮（"新建连接"）、没有最近连接、没有示例。
而且它作为**一个标签存在**，开第一个连接后消失——用户会以为"标签被丢了"。

### 3.5 SFTP 双栏（截图 4）

1. **绝大多数文件操作不可见**：上传/下载/新建目录/改名/删除/刷新全在右键
   菜单（`pane.rs:505-533`）；双击文件即传输是隐藏行为。
2. **远程/本地不对称**：远程工具栏内容左对齐，本地用 spacer 推到右
   （`pane.rs:368-372`）；两边按钮集也不同，视觉重心一左一右。
3. **路径重复**：状态行已含 cwd（"已连接 … — /root"），下一行路径框又是
   `/root`（`mod.rs:310-321`、`pane.rs:401-408`）。
4. **列被挤扁**：截图里"大小""权限""修改时间"三列紧贴，修改时间只剩
   `2026-04-15 11:35`，长一点就截断（`pane.rs:73-127` 的 `shrink` 策略是对的，
   但没有列宽持久化，也没有"窄屏自动隐藏次要列"的规则）。
5. **目录的"大小"显示"目录"**（`pane.rs:193`）——语义列里放非数量文本。
6. **列表图标全彩**（`folder`/`text-x-generic`）与侧边栏 symbolic 不同风格。
7. **列显隐菜单是自绘 ✓/·**（`pane.rs:536-628`，注释说明是为绕 Deepin
   主题的重绘 bug）——可用的 workaround，但视觉上是字符画，应换
   `CheckButton` 或菜单项勾选态。
8. **面板标题只是加粗"远程/本地"**（`pane.rs:258-262`），没有路径、没有
   连接状态、没有当前选中数。

### 3.6 终端与状态条（截图 4）

1. 广播/日志/录制三行状态条是 `Button/Label` 竖排（`term.rs:420-442`），
   文案用 `⤷`/`●` 前缀（`term.rs:564-573`、`831`、`883`），没有背景色——
   "正在广播按键"这种高危状态看起来像普通灰字。
2. 搜索条与状态条高度不统一；搜索条默认收起，没有"找不到"反馈。
3. 右键菜单是一个 `Popover` + 13 个 flat 按钮（复制/粘贴/重连/左右分屏/
   上下分屏/关闭分屏/3 个复选/打开回放/回放最近，`term.rs:1291-1492`）：
   无图标、无分组标题、无快捷键提示、无危险色。

### 3.7 连接管理（截图 2）

1. 列"来源"全是"ssh config"/"自定义"，**信息量低且无视觉区分**。
2. 名称与地址**重复**（`writes.ink:6001` ↔ `kube@writes.ink:6001:6001`），
   地址列被截断。
3. **没有搜索/过滤**（侧边栏有、管理器没有）；条目多了只能滚。
4. 没有分组（自定义/只读混在一张表）、没有排序、没有列宽记忆。
5. 9 个按钮一行（见 S5）；"删除"无确认（见 S7）。
6. 顶部提示是一行 `<small>` markup（`connmgr.rs:1035-1040`），字小、灰、
   位置在边框内第一行，像附注而不像引导。

### 3.8 新建/编辑连接、手动连接

1. 标签右对齐 + 输入框满宽（`connmgr.rs:722-737`、`914-925`）：中文标签短，
   视觉上形成大片"空白-输入框"的锯齿。
2. 协议切换用 `set_visible` 显隐 8 行（`connmgr.rs:760-808`）：切换时对话框
   高度跳变，行位置重排，用户手上的鼠标会点错。
3. 端口是 `Entry` 而非 `SpinButton`（`connmgr.rs:678`），无范围提示。
4. 密码字段 tooltip 里写"明文保存在 connections.ini"（`connmgr.rs:683-685`）——
   安全说明藏在悬停里；有了凭据库之后这句已过时（vault 解锁时只进加密库）。
5. 端口转发是 8 行 `TextView` 文本域（`connmgr.rs:704-720`），规则语法写在
   tooltip 里——这是最该做成表格 + 行的表单。

### 3.9 私钥管理器（截图 1）

1. **字面量 `\n` + 不换行把窗口撑到 1712px**（`keyui.rs:29-33`）——本次最刺眼
   的缺陷。
2. 密钥列表**无列头**：名称/算法/指纹挤在三段，`读不了` 红字在最右且无图标，
   错误原因只在 tooltip（`keyui.rs:274-284`）。
3. 没有**行内操作**（复制公钥、查看、删除、设为默认），所有能力只有"生成"和
   "转 OpenSSH"。
4. 生成区一行塞 5 个控件（下拉/3 输入框/按钮，`keyui.rs:50-73`），**没有标签**，
   全靠 placeholder——输入后标签消失，用户不记得这格是"注释"还是"口令"。
5. "选 .ppk…"把路径用 `show_error` 弹窗告知（`keyui.rs:191-200`），
   一次选择产生两条弹窗。

## 6. 实施注记（避免踩坑）

1. **GTK4 无 `StyleManager`**（`theme.rs:7-10` 已说明），主题仍走
   `CssProvider` + `@define-color`；把新令牌加进 `BASE` 与三套主题，
   业务类（`.pp-ok` 等）也定义在 `BASE` 里。
2. **`CellRendererText.foreground` 只能用 RGBA**：新增
   `theme::rgba(&str) -> Option<gdk::RGBA>`，在 `apply()` 后广播一次
   "主题变了"，队列/侧边栏重刷行颜色。
3. **markup 里的 `foreground=` 不要再用**；用 `Label` + 类。
4. **CSS 类要挂在 `Window` 上才算"作用域"**：紧凑模式 `pp-compact` 目前只给
   主窗，需要给所有 `gtk::Window` 统一加（可在对话框构造函数里统一加，
   或监听 `Window::list_toplevels` + `map`）。
5. **`GtkDialog` 避免底部按钮与标题栏 × 重复**：改用 `AlertDialog`/自建
   `Window` + HeaderBar，或至少去掉多余按钮。
6. **Pango markup 里的 `${...}` 安全**（`${` 不是 markup 语法），但
   `&`/`<` 必须转义——`quickcmd.rs:316` 已有内容来自用户输入的风险。
7. **保持 CLI/文案兼容**：所有用户可见文案改动只允许"增补"，不得改变
   `--print-config`、spawn argv、askpass 协议相关字符串（AGENTS.md 核心规则 2/3）；
   UI 文案改动前后跑 `bash rust/tools/compat_check.sh`。

### 7.2 顺带查出的三个"更根本"的 bug

这三条不在原 P0 清单里，但不修的话**主题功能等于不存在**：

1. **`apply()` 把带 `BASE_PLACEHOLDER` 的原始 CSS 交给 GTK**（`theme.rs`）。

## 11. 信息架构：把「新建」和「管理」拆开（2026-10-18 晚）

### 11.1 问题

用户反馈：**连接管理和会话列表感觉重复；点「新建连接」却先弹连接管理器，
还要再点一次「新建」**。

根因是同一个对话框被当成三种东西用：

| 意图 | 实际行为 |
|---|---|
| 新建一台机器 | 打开连接管理器（一个 CRUD 列表）→ 再点「新建」 |
| 从列表里挑一台 | 打开同一个管理器 → 点「连接」（或双击） |
| 管理/导入导出 | 还是它 |

而侧边栏本来就已经是「连接列表」（最近 / 自定义 / ssh config），
于是"列表"存在两份，"新建"多一步。

### 11.2 新分工

| 意图 | 入口 | 行为 |
|---|---|---|
| **新建连接** | 顶栏「＋ 新建连接」/ 标签栏「+」/ 文件菜单 / 欢迎页 / 侧边栏底部 | **直接开新建表单**（一步到位） |
| **选择已有** | 侧边栏双击 / 回车（唯一选择器） | 当前窗口开新标签 |
| **管理连接** | 文件 → 连接管理… / 侧边栏 ⋯ | 增删改、导入导出、凭据库/私钥；双击 = 连接（回当前窗口），右键另有「在新窗口打开」 |

### 11.3 新建表单的三个出口

新建对话框不再只有一个「保存」：

- **仅连接**：不落盘，直接在当前窗口开标签（临时连一台机器）；
- **保存**：写进 `connections.ini`，对话框关闭，侧边栏立即出现新条目；
- **保存并连接**（默认回车）：保存 + 开标签。

### 11.4 实现要点

## 12. 主操作去重：同屏只留一个「新建连接」（2026-10-18）

### 12.1 问题

## 13. 侧边栏右键菜单 + 「最近」去重（2026-10-18）

### 13.1 侧边栏条目的右键菜单

以前改端口/删连接都要先进连接管理器。现在按行类型给不同的动作：

| 行类型 | 菜单项 |
|---|---|
| 最近项 | 连接 / **从最近中移除** / 复制地址 |
| 自定义连接 | 连接 / 在新窗口打开 / **编辑…** / **删除** / 复制地址 |
| ssh config（只读） | 连接 / 在新窗口打开 / 复制地址 |

- 编辑复用同一个表单（预填、保存后侧边栏立即重读）；
- 删除二次确认，文案与连接管理器一致；只读条目不出现编辑/删除；
- 「连接」在当前窗口开标签；「在新窗口打开」保留堡垒机多窗口用法；
- 实现注记：右键菜单改成**建一次 `Popover`、每次点击只换里面的按钮**。
  用 `PopoverMenu` + action 时，"在右键手势里现建弹层"的菜单项点击不会被
  激活（点一下只会把弹层关掉）；按钮版把回调直接连在控件上，行为可预期。
  另外菜单按行类型只列适用项，不再用"禁用态"表达不适用。

### 13.2 「最近」同机多条

根因不是没写去重——`recent::push` 早就按 `host+port+user` 去重了，**是端口没归一化**：
命令行默认端口 0、界面连接端口 22，被当成两台机器，于是最近里出现两行。

- `load()` 时归一化端口（0 → 22）并**保序去重**（老文件里的重复也一并合并）；
- `push()` 先删同键再置顶；
- 去重键 = 用户 + 主机 + 端口（标签/来源不参与——同一台机器从侧边栏和命令行
  各开一次不该留两行）；
- 「最近」分组 tooltip 写明合并规则：「同一个 用户/主机/端口 只保留最近一次」；
- 右键「从最近中移除」可手工清掉不需要的条目。

### 13.3 验证

- 构造 `recent.ini` 三条（a:22 / a:0 / b:22）→ 侧边栏只显示 2 条；
- 右键逐项实测：移除（`recent.ini` 少一条）、编辑（表单预填 demo-box）、
  删除（确认后条目消失、侧边栏刷新）、连接（开标签）、复制地址（`xclip`
  读到 `root@10.0.0.10:22`）；
- `cargo test` 201/203、`compat_check.sh` 80/80 全绿。

## 15. 终端右键菜单越点越长（2026-10-19）

现象：终端里右键第一次/第二次菜单不一样，第三次干脆不弹。

根因：菜单本体（复制/粘贴/重新连接）在 `install_context_menu` 里只建一次，
分屏/广播/日志/录制那段"扩展区"是**每次右键往同一个 vbox 里 append**，
从不清空。于是第 2 次菜单条目翻倍，第 3 次高过屏幕，Popover 定位失败就不再
显示——看起来像"右键没反应"。

修法：扩展区放进独立的 `extra_box`，每次弹出先 `remove` 掉全部子控件再重建。
勾选状态仍然每次从真实状态读，所以三块面板/分屏各自打开时内容一致。

验证：同一坐标连续右键 3 次，三张截图逐字节相同（菜单条目不再累积）。

## 16. 面板开关按钮点一下变空白（2026-10-19）

现象：远程面板的「显示隐藏文件」「跟随终端目录」一旦切到选中态，图标位置就
只剩一块空白（按钮还在、占着位）。

根因在主题 CSS 的叠加顺序，跟按钮本身无关：

```css
button:checked { background-color: @pp_accent; color: @pp_on_accent; }
button.flat   { background-color: transparent; }   /* 把底改透明，颜色没改 */
```

两个 flat 开关选中后 = 透明底 + `on_accent` 前景；浅色主题的 `on_accent`
是白色，于是**白图标画在白面板上**，看起来就是空的。跟随目录默认就是选中，
所以连上 SFTP 后它一直是"隐形"的。

修法：给平面开关的选中态单独一条规则（`button.flat:checked`）——浅强调底 +
正常文字色；hover 再深一档。两种状态都看得见，也能一眼分辨开/关。

验证：独立 GTK 探针（同一个 flat ToggleButton 的未选/选中两态）截图前后对比，
并把 `button.flat:checked` 加进主题 CSS 的回归断言。

## 19. 菜单信息架构：按作用域拆“会话”（2026-10-21）

用户反馈：**端口转发为什么在「会话」底下**。检查后发现「会话」是个杂物抽屉，

- 连接级：重新连接 SFTP、端口转发、数据库、会话选项；
- 终端级：左右/上下分屏、关闭当前终端、按键广播、日志、录制、回放；
- 全局：私钥、凭据库、外观、快捷键。

按“这个动作改的是哪一层”重新分：

| 菜单 | 内容 |
|---|---|
| 文件 | 新建连接 / 连接管理 / 关闭标签 ｜ 导入 / 导出 ｜ 退出 |
| 编辑 | 复制 / 粘贴 ｜ 终端查找 |

| 工具 | 私钥管理器、凭据库 |
| 帮助 | 快捷键一览、关于 |

要点：

- 「会话」改名「连接」：端口转发、数据库通道、保活/字号覆盖都挂在当前这条
