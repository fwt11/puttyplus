## PuTTYPlus {{VERSION}}

PuTTY 兼容的 SSH 终端 + 图形化 SFTP + 数据库工作台（Linux / GTK4）。

**下载**

- `puttyplus_{{VERSION}}-1_amd64.deb` —— x86-64 的 Debian / Ubuntu 等发行版安装包
  （依赖 GTK ≥ 4.18、VTE ≥ 0.80）
- `puttyplus_{{VERSION}}-1_arm64.deb` —— arm64（aarch64）同上，树莓派 / ARM
  服务器 / ARM 笔记本用这个
- `puttyplus-linux-x86_64.tar.gz` —— 免安装的单个可执行文件（x86-64）
- `puttyplus-linux-aarch64.tar.gz` —— 免安装的单个可执行文件（arm64）
- `puttyplus-windows-x86_64.zip` —— **Windows 版**（实验）：解压后双击
  `puttyplus.exe` 即可（GTK 的 DLL 都在包里；图标主题没带，可能显示不出
  图标，不影响功能）

校验和见 `SHA256SUMS`。

**本版要点**

本版把**数据库工作台**按 SQLite 客户端 dbx 的简洁性重做了一遍（拿 dbx 点了
一遍按钮逐条对比）。三件事：

- **筛选＝一个宽 WHERE 框，写完回车就查**。以前要先点「🔽 过滤条件」弹窗、
  再点「+ 条件」，条件还摊成一行行的标签；现在工具条上就有一个蓝色的
  **WHERE** 输入框，写完**回车**重新查库。旁边的 ▾ **条件助手**给不记得
  列名 / 不记得引号写法的人用：挑列 + 运算符 + 值，它**按列类型转义**
  （整数列不加引号、文本列加引号）生成一段一定能跑的条件，**填进 WHERE 框**，
  填完可以接着改，按回车才生效。
  ⚠️ 界面上有两个筛选：**服务端**那个是蓝色的「WHERE」（重新查库），
  **本地**那个叫「**筛本页**」（只在已取回的这一页里筛，不查库）—— 名字
  分开了，不用点错才发现不是一回事。
- **工具条收回成一行，底栏开始报账**。条件条以前独占一行、条件标签再占
  一行 ⇒ 网格被挤掉一大截；现在都并进工具条那一行，**网格多出两行**。
  底栏改成三段：左边是**行数 · 耗时 · 待保存项数**，中间**常驻显示当前正在
  执行的 SQL**（以前只能去日志里翻「你到底发了什么 SQL」），右边是
  **「统计总行数」** + 每页行数 + 分页控件。
  ⚠️ 「总行数」是当场跑一次 `count(*)` 数出来的**真值**，跟对象树「详细」
  模式下那个带 ≈ 的估算值（PG 的 reltuples / MySQL 的 TABLE_ROWS）不是
  一回事。只有表浏览页签能数（手写查询不知道是哪张表，那颗按钮是灰的）。
- **表属性页多了「建表语句」**：属性页下面多一段 `CREATE TABLE` 原文，带
  语法高亮、**只读**，旁边有「复制」按钮（贴到别处、存成文件都方便）。
  ⚠️ 视图没有这一段 —— 视图的定义得问数据库自己（`pg_get_viewdef` /
  `SHOW CREATE VIEW`），所以只写一句说明，不给一段拼错的 DDL。

**上一版（0.5.4）的内容照旧**：

- **修：堡垒机上分屏失败**。分屏的那个终端会报
  「WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!」+
  「Host key verification failed.」，**直接失败**（退出码 255）。
  根因：堡垒机在**本地开一个随机端口**，我们连的就是那个端口，而堡垒机
  的隧道**按访问轮换主机密钥** ⇒ 按 `[地址]:[端口]` 记的
  `~/.ssh/known_hosts` **必然对不上** ⇒ 被直接挡住。
  ⇒ 现在**连 `127.0.0.1` 这类回环地址时不再查也不写** `known_hosts`
  （普通地址照旧做主机密钥校验）。

**再上一版（0.5.3）的内容照旧**：

- **连接中枢：同一台服务器只开一条 SSH 连接**。SFTP 文件面板、端口映射
  （`-L`/`-R`/`-D`）、数据库工作台、交互终端**全部复用同一条 SSH 连接**
  （各自开自己的通道）⇒ 连同一台服务器只认证一次、只占服务器一个连接位，
  跨标签页也复用。
  ⚠️ **终端并入共享连接后不再走你自己的 `ssh`** ⇒ `~/.ssh/config`
  （ProxyJump 等）不生效 ⇒ 需要的话在**首选项 →「终端」页 →「终端连接
  方式」**切回「spawn 自己的 ssh」（或设 `PP_TERM_SSH=spawn`）。
- **修：上传大文件时界面整体卡死**（用户报「上传 1GB 文件时界面完全卡住、
  菜单都点不动、进度停在 2% 然后突然跳到 80%」）。根因有两个，都修了：
  进度更新与呼吸动画**每帧把整个文件列表重画一遍**（一帧 59ms ⇒ 远程桌面
  上界面冻住）⇒ 改成**只重画正在传的那一行**、进度通知**限流到每 100ms
  一次**；传输与面板请求**挤同一条 SFTP 通道** ⇒ 传输改走自己那条通道
  （**仍是同一条 SSH 连接**，不多占服务器连接数）。
- **传输队列按钮的角标重做**：数字画在一个**蓝色圆点**里，**外面套一个
  真的在转的圈** ⇒ 一眼就知道「还在传」，数字告诉你「还剩几件」；传完
  圆点连数字一起消失。
- Windows 版：数据库工作台与端口映射开放、PATH 里有 `ssh.exe` 就 spawn
  它、ConPTY 的 UTF-16 编解码修正；ghostty 成默认引擎且可在首选项切换；
  编辑器查看上限可配置、非文本文件可 hex 打开；大小列定宽、横向滚动条
  自己画、传完「完成」渐隐、选中态底色不再压住文字、数据库列头换成齿轮。

**Windows 版的已知差异**（Linux 版不变，仍然 spawn 用户自己的 `ssh` ⇒
`~/.ssh/config`、agent、ProxyJump 的语义全都在）：

- Windows 版终端**不读 `~/.ssh/config`**（别名由本程序自己展开，
  `HostName`/`Port`/`User`/`IdentityFile` 生效，但 **ProxyJump 不支持**）；
- Windows 上数据库走回环 TCP ⇒ 远端 `pg_hba.conf` 需要放行 TCP + 密码
  认证（Unix 那边走本地套接字，多半是 peer/trust，不校验密码）；
- 端口转发走本程序自己的进程内转发，不经 `ssh -L/-R/-D`。

**特性**：命令行与 PuTTY 兼容（可顶替 PuTTY 部署在堡垒机上）· 终端 + SFTP
双栏同窗口 · 终端左右 / 上下分屏 · 数据库工作台（PostgreSQL / MySQL，
通道复用当前 SSH 连接）· 凭据库（argon2 + AES-GCM）· 中英文界面 ·
会话录制与回放（asciicast）· 串口会话。

详见 [README](https://github.com/fwt11/puttyplus#readme)。
