## PuTTYPlus {{VERSION}}

PuTTY 兼容的 SSH 终端 + 图形化 SFTP + 数据库工作台（Linux / GTK4）。

**下载**

- `puttyplus_{{VERSION}}-1_amd64.deb` —— x86-64 的 Debian / Ubuntu 等发行版安装包
  （依赖 GTK ≥ 4.18、VTE ≥ 0.80）
- `puttyplus_{{VERSION}}-1_arm64.deb` —— arm64（aarch64）同上，树莓派 / ARM
  服务器 / ARM 笔记本用这个
- `puttyplus-linux-x86_64.tar.gz` —— 免安装的单个可执行文件（x86-64）
- `puttyplus-linux-aarch64.tar.gz` —— 免安装的单个可执行文件（arm64）

校验和见 `SHA256SUMS`。

**本版要点**

- **有 Windows 版了**（实验）：终端会话、SFTP 文件面板、命令行参数契约
  三样跟 Linux 版一致。终端内核换成 Ghostty 的（libghostty-vt）并自己画字
  （cairo + pangocairo），中文输入法自己挂；**SSH 是我们自己实现的**
  （russh 直接驱动终端内核）⇒ Windows 上**不用装 `ssh.exe`，也不用装
  `plink`**，跑起来不需要任何外部程序。
- **命令行参数跟 PuTTY 逐条一致**：Windows 版对着**同一批 73 条黄金基准**
  跑，PASS=73 FAIL=0 ⇒ 堡垒机那边照旧用 PuTTY 的调用方式拉起本程序，
  不用改一个字。
- **两个平台的密码现在是同一套**：以前 SFTP 面板、终端、分屏是三条各自
  独立的连接，同一个会话要分别输密码；现在只问一次，三边共用这一份。
- **Windows 上也能用 ssh-agent 了**：密钥加进 agent 之后，Linux 上本来
  就是免密的，Windows 上以前却还要输密码——那才是"两边看起来像两个
  软件"的真正原因，现在两边都能走 agent（Windows 走命名管道）。
- **终端敲键盘有反应了**：以前在 Windows 上敲键盘像没反应（按键被丢掉
  了），现在字能出来；点完文件面板再点回终端也能立刻接着打字。
- 修了一个 Linux 上的老毛病：**每开一个终端都往 stderr 喷一条
  GLib-CRITICAL**（VTE 那边要读程序名，我们一直没设）。
- **首选项 →「终端」页能挑字体了**：字体名下拉里列的是本机装了的**等宽
  字体**（终端用比例字体没法对齐）；**字体和字号改完立刻生效**——正在看的
  那个终端当场就变，不用重开。
- **切换界面语言也立刻生效**：以前改语言要重启应用，现在顶栏、菜单、侧栏、
  首选项窗口当场换成新语言（**正在跑的终端不受影响**，不会被断开）。
- 侧栏那个「凭据库 已锁定」标志**改成一个图标**了（不占地方），点它**只
  解锁**，不会再弹一个列满库里凭据的窗口——要看库里的内容，去菜单「凭据库…」。

**Windows 版的首版范围**：终端 + SFTP + 命令行契约。数据库工作台的代码
保留但**入口隐藏**（会提示"Windows 版尚未验证"）；桌面通知暂不做；会话
录制在 Windows 上暂不可用。

**Windows 版的已知差异**（Linux 版不变，仍然 spawn 用户自己的 `ssh` ⇒
`~/.ssh/config`、agent、ProxyJump 的语义全都在）：

- Windows 版终端**不读 `~/.ssh/config`**（别名由本程序自己展开，
  `HostName`/`Port`/`User`/`IdentityFile` 生效，但 **ProxyJump 不支持**）；
- 端口转发走本程序自己的进程内转发，不经 `ssh -L/-R/-D`。

**特性**：命令行与 PuTTY 兼容（可顶替 PuTTY 部署在堡垒机上）· 终端 + SFTP
双栏同窗口 · 终端左右 / 上下分屏 · 数据库工作台（PostgreSQL / MySQL，
通道复用当前 SSH 连接）· 凭据库（argon2 + AES-GCM）· 中英文界面 ·
会话录制与回放（asciicast）· 串口会话。

详见 [README](https://github.com/fwt11/puttyplus#readme)。
