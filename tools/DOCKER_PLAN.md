## 二、我们的架构约束（**决定了怎么做**，别照抄 dbx）

| 约束 | 含义 |
|---|---|
| **一台服务器一条 SSH 连接**（连接中枢 `backend/hub.rs`） | 容器视图**不能自己开连接**。要在**共享连接**上开 **exec 通道** ⇒ 复用 `hub::acquire()` 拿 `SharedConn` ⇒ `shared.session()` ⇒ `ShellChannel::open_exec(...)`（**已有**，终端/分屏在用） |
| **界面在连接页的子标签区** | 容器视图做成**子标签**（和「数据库」工作台平级）⇒ 不新增主标签（主标签＝一个会话） |
| **不引入新依赖** | 仓库里**没有 serde_json**，也不打算加 ⇒ 用 `docker --format` 的 **Go 模板**直接吐我们要的字段，**不解析 JSON** |
| **用户可见文案全中文** | 状态、错误、提示都中文（Rust-only 功能，不涉及 C 版对齐） |
| **别整表重画** | 项目踩过「整表重画把主线程拖死」的坑（上传卡死事件）⇒ 列表用 `ListStore` **差量更新** |
| **别在用户机器装东西** | 容器命令全在**远端**跑；本机不需要 docker |
| **不自动 sudo** | 远端权限不足时**给中文提示**，不擅自 sudo（会要密码、会留痕迹） |

## 三、技术方案

### 3.1 后端：`src/backend/docker.rs`（新模块）

一条命令 = 一条 exec 通道（通道很轻，**不是新连接**）：

```rust
// 走共享连接 ⇒ 一台服务器一条 SSH 连接这条硬约束不受影响
let shared = hub::acquire(ServerKey::new(host, port, user), &creds).await?;
let session = shared.session().clone();
let ch = ShellChannel::open_exec(session.as_ref(), &cmd, 80, 24, false).await?;
// 读 stdout 直到 Exit(退出码)
```

**命令清单**（全部用 Go 模板输出，**不解析 JSON**）：

| 用途 | 命令 |
|---|---|
| 探路 | `command -v docker` → `docker version --format '{{.Server.Version}}'` |
| 列表 | `docker ps -a --format '{{.ID}}\t{{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}\t{{.Label "com.docker.compose.project"}}'` |
| 资源占用 | `docker stats --no-stream --format '{{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'` |
| 详情 | `docker inspect --format '{{.Name}}\t{{.Config.Image}}\t{{.Created}}\t{{.State.Status}}\t{{.State.StartedAt}}\t{{.RestartCount}}\t{{.HostConfig.RestartPolicy.Name}}\t{{.Config.User}}\t{{.Config.WorkingDir}}\t{{.Path}}\t{{.Args}}' <id>` |
| 端口/挂载/环境 | `docker inspect --format '{{range .NetworkSettings.Ports}}…{{end}}'` / `{{range .Mounts}}…{{end}}` / `{{range .Config.Env}}…{{end}}` |
| 日志 | `docker logs -f --tail 200 <id>`（长跑 ⇒ 独立通道 + 流式读） |
| 终端 | `docker exec -it <id> /bin/sh`（**复用现成的终端控件**） |
| 启停 | `docker start / stop / restart <id>`（**写操作 ⇒ 二次确认**） |

⚠️ **分隔符用 `\x1f`（单元分隔符）而不是 `\t`**：镜像名/状态里可能有空格和制表符。

### 3.2 前端：`src/panel/dockerui.rs`（新模块）

- 做成**子标签页**（图标 + 「容器」标题），照 `panel/dbui.rs` 的挂载方式
  （`sub.add_page_icon_kind(...)` + `add_close_hook` 收尾）。
- 列表：`gtk::TreeView` + **`gtk::TreeStore`**（⚠️ **不是 `ListStore`**）。
  - **为什么是树**：用户 2026-11-15：「容器列表要中要体现单独的容器和使用
    docker-compose 组织的容器，**每个 docker-compose 项目点开之后才显示它
    组织的容器**」⇒ compose 项目是**父行**（默认收起），独立容器是**顶层行**。
  - 层级由 `docker ps --format` 里的 `{{.Label "com.docker.compose.project"}}`
    标签决定（没这个标签的容器 ⇒ 顶层行）。
  - ⚠️ **刷新要保住展开状态**：清空模型时 GTK 会发 `row-collapsed` ⇒ 用信号
    记账会被「清空」抹掉 ⇒ 改成**清空前**问一次 `view.row_expanded()`。
- 详情：在**子标签区里再开一个子页**（像数据库工作台的「对象树 → 详情」），
  详情页里再分「概览 / 日志 / 终端」几个页签。
- 监控曲线：**自己画**（`gtk::DrawingArea` + cairo）——项目里没有图表库
  （`settingsui.rs` 已有 `rounded_rect` 那种 cairo 写法可参考）。
- 日志/终端：复用 `termview::TermView`（进程内 SSH 的 pty 通道已经有）。

### 3.3 刷新

- 自动刷新（默认 7 秒，可关）+ 手动刷新 + 「上次刷新 hh:mm:ss」。
- 命令在**后台 tokio 任务**里跑（`hub::runtime()`）⇒ 结果回主线程更新表格
  ⇒ **不卡 UI**。
- ⚠️ **容器表格是整表重建**（不是 `ListStore` 差量）：① 树形模型（`TreeStore`）
  换父子关系时差量更新很难写对；② 一台服务器上的容器**就几十个** ⇒ 重建
  的成本可忽略。
  ⇒ 但**别在每帧重建**：只在「刷新回来 / 过滤变了 / 搜索变了」时重建一次
  （项目踩过「整表重画把主线程拖死」的坑，见 AGENTS.md）。

- ⚠️ **实测踩出来的三个坑**：
  1. **`docker logs -f` 断开后不会自己退出**（实测：ssh 客户端断了，远端
     还留着 `docker logs -f` 进程）⇒ 用户每开关一次日志就在服务器上漏一个
     进程（容器安静时它不写数据 ⇒ 收不到 SIGPIPE ⇒ 能挂到天荒地老）。
     ⇒ **看门狗**：看门狗读**通道的 stdin**（通道一关就是 EOF ⇒ 杀
     `docker logs`）；`docker logs` 自己先退出 ⇒ 收掉看门狗。
     ⚠️ 杀掉后台任务时 shell 会打一句 "Terminated" ⇒ 会混进日志 ⇒ 子 shell
     的 stderr 丢到 `/dev/null`（但 `docker logs` 自己的 stderr 仍用
     `2>&1` 并进 stdout —— 那是 **docker 进程**的 fd2，不是 shell 的）。
  2. **`selected` 只有测试钩子会写** ⇒ 真实流程里详情消息被当成「过时的」
     丢掉 ⇒ **详情区永远不显示、启停按钮点了没反应**（阶段 110 的 bug，
     冒烟当时用注入数据把它掩盖了）⇒ 改成**选中时立刻记**。
  3. **刷新重建表格会清掉光标** ⇒ GTK 发 `cursor-changed` ⇒
     `clear_detail()` 把 `selected` 清空 ⇒ **刷新一次，用户刚选中的容器就没
     了** ⇒ 重建的**整段**都要算「程序性」（`restoring`）。
- ⚠️ **冒烟里的一条 GTK 行为**：`set_cursor` 对**看不见的行**（收着的项目里
  的子行）**不生效** ⇒ 要选 compose 组里的容器 ⇒ 得先展开项目。

    ⇒ 不用二次确认）⇒ **另开一个窗口**（详情区只有 ~160px ⇒ 塞终端没法用）
    ⇒ 复用 `TermView`（`src/term.rs` 的 `new_term_backend()` 改成 `pub(crate)`）；
    关闭 ⇒ `ShellChannel::close()` ⇒ 远端不留孤儿 `docker exec`；
  - ⚠️ **顺手修了一个藏得很深的真 bug**：**远程命令的退出码恒为 0**
    （详见下面的「退出码」一节）。
- ⚠️ **实测踩出来的坑**：
  1. **exit-status 排在 EOF 后面** ⇒ 以前「一收到 EOF 就收尾」⇒
     **退出码永远是 0** ⇒ 「挨个试哪个 shell 能用」**根本没试**（探测永远
     「成功」）⇒ 容器里没有 `/bin/sh` 也会说「有」。
     ⇒ 修法：`next_event()` 收到 EOF **不算结束**（继续等 exit-status/close，
     EOF 之后最多再等 2 秒兜底）；退出码只报一次。
  2. **两个 pty 才对**：SSH 通道也申请 pty（`pty = true`）⇒ 两边都是 tty
     ⇒ docker 不会报「the input device is not a TTY」。
     ⚠️ 只去掉其中一个 ⇒ 冒烟的「终端里有回显」那条会红（实测）。
  3. **退出码修好之后，`classify_failure` 里那些分支才不是死代码**
     （以前 `code` 恒为 0 ⇒ 根本走不到）⇒ 补了「容器不在了」的识别。
- ⚠️ **容器的 shell 探测命令**用 shell 内建的 `exit 0`，**不要**用 `true`
  那个二进制 ⇒ distroless 那种镜像里未必有。

- 详情区多第三个子页「监控」⇒ 4 个指标卡（CPU / 内存 / 网络 / 磁盘）＋ 4 张
  cairo 折线图（每张图两条线：收 / 发）。
- ⚠️ **采样方案改了**：原计划「每 2 秒跑一次 `docker stats --no-stream`」，
  **实测 `--no-stream` 单次就要 2 秒**（docker 内部要采两次 cgroup 差值）⇒
  等于远端**几乎连续**在跑 docker stats ⇒ 改成**持续模式**：
  - `docker stats --format '<4 个字段>' <容器>`（**只盯选中的那一个**，
    不统计全部容器）；
  - **持续模式带 ANSI 转义**（表格重绘：`\x1b[H` / `\x1b[K` / `\x1b[J`）⇒
    客户端要**剥掉**（`strip_ansi`，纯函数）；
  - 客户端**每 2 秒出一个点**（`StatsSampler` 节流）⇒ 曲线才好看；
  - 网络 / 磁盘是**从容器启动起的累计值** ⇒ **差分**才是速率（容器重启
    计数归零 ⇒ 那一次差分丢掉，否则会画出一根巨大的尖峰）。
- ⚠️ **切页即停**：日志页与监控页**两流互斥**（切走就停）⇒ 远端不留孤儿
  `docker stats`；换容器 ⇒ 停旧流 ＋ 清曲线 ＋ 立刻起新流。

### 阶段 116：容器内文件浏览 ＋ 上传 ＋ 下载 —— ✅ **2026-11-16 完成**

- 详情区多第四个子页「文件」⇒ **路径栏 ＋ 文件表 ＋ 上传 / 下载 / 查看**。
- ⚠️ **容器里没有 SFTP** ⇒ 浏览只能 `docker exec` 跑 `ls -lA`（解析 `ls` 的
  长格式：权限串第 1 字符判类型、第 5 字段是大小、第 9 字段起是名字）。
- ⚠️ **传输走 `docker cp` 的归档流**（用户 2026-11-16 提问后改的）：
  - **上传**：本地 `tar -cf - -C <父> <名字>` 的字节流 ⇒ 喂给远端
    `docker cp - <容器>:<目录>/` 的 stdin ⇒ **Docker 自己解包**；
  - **下载**：远端 `docker cp <容器>:<路径> -` ⇒ stdout 就是 **tar 归档**
    ⇒ 落本地临时文件 ⇒ 本地 `tar -xf` 解开（归档的根就是 basename ⇒
    解出来正好是 `<本地目录>/<名字>`）；
  - ⚠️ **实测出来的三条语义**（2026-11-16 本机 docker 29.9.3 验的）：
    ① `docker cp -` 的**目标必须是目录**（给文件路径报「must be a
    directory」）⇒ **文件名由 tar 归档里的路径决定**；
    ② 归档里 stderr 必须隔离（`2>/dev/null`）⇒ 否则报错混进归档流 ⇒
    本地解不开；
    ③ 归档的**根就是 basename** ⇒ 不用 strip-components。
  - ⇒ 好处：**容器里不需要有 cat/tar**（distroless 镜像也能用）＋ 权限/
    时间戳由 Docker 官方通道保证 ＋ **二进制保真**（冒烟里有字节级断言）。
  - ⇒ 代价：本地要有 `tar`（Windows 10+ 自带 bsdtar）。
- ⚠️ **写操作**：上传是写操作 ⇒ **二次确认**（默认焦点落在「取消」）。
- ⚠️ **「查看」只读且限 256 KB**（超了让用户下载，别把 TextView 撑死）。
- ⚠️ **传输带看门狗**：远端命令不退出（历史上踩过：`close()` 不发 EOF ⇒
  远端 `cat` 一直等）⇒ **120 秒没进展就报「传输卡住了」**，别把界面挂死。

## 五、风险与坑

1. **权限**：远端用户不在 docker 组 ⇒ `permission denied … /var/run/docker.sock`
   ⇒ 中文提示「当前账号没有访问 Docker 的权限（需要加入 docker 组，或改用 sudo
   登录）」。⚠️ **不自动 sudo**。
2. **没装 docker**：`command -v docker` 空 ⇒ 「远端没有找到 docker」。
3. **守护进程没起**：`Cannot connect to the Docker daemon` ⇒ 「远端的 Docker
   服务没起来」。
4. **老版本 docker**：Go 模板字段有版本门槛（`{{.Label "x"}}` 要 17.06+，
   `docker stats --format` 要 18.09+）⇒ 先探版本 ⇒ 老版本降级到 tab 格式。
5. **字段里有空格/制表符** ⇒ 分隔符用 `\x1f`。
6. **刷新卡 UI**：⇒ 后台跑命令 + 差量更新。
7. **写操作误触** ⇒ 启停/重启二次确认。
8. **Podman**：`podman ps --format` 的模板和 docker **不完全一样** ⇒ 首期只支持
   docker，podman 放到后面（探测到 podman 时给提示即可）。
9. **客户端是 Windows、服务器是 Windows**：没有 docker ⇒ 提示即可（命令在远端跑，
   客户端平台不影响）。
