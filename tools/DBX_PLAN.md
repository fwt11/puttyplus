# 对标 dbx 的改造计划（阶段 43 起）

> 依据：用户 2026-10-28 提供的 dbx 三张截图（新建表 / 填字段 / 数据网格）。
> 目标：把数据库工作台做成「看着像正经数据库工具 + 干的事一样多」。
>
> **执行方式**：一个阶段一个提交，阶段结束跑全量回归（`cargo test --lib` +
> `compat_check.sh` + 涉及的冒烟 / 真库 e2e），然后**重新 `build_deb.sh` 打包
> 并 `dpkg -i` 安装**——用户跑的是 `/usr/bin/puttyplus`，不重装就看不到改动。
>
> **每阶段的通用验收**：
> - 新加的逻辑要有**单测**（纯函数）或**冒烟**（真 GTK 行为）；
> - 涉及真库的要在 PG / MySQL 两边跑 `examples/db_ui_e2e.rs`；
> - ⚠️ **新加的 e2e 断言要验证过它真抓得住**（临时回退修复跑一遍，确认失败）；
> - 界面改动要有**截图**（`examples/ui_shot.rs` 或 e2e 的 `--shot-*`）。

---

## 一、总览：dbx 的信息架构 vs 我们的现状

dbx 的骨架（从上到下）：

```
顶栏工具栏（新建连接/新建查询/数据传输/驱动管理/插件中心/更多）
├─ 左侧对象树（搜索 + 显示已连接开关 + 列表/详情视图）
└─ 右侧工作区
   ├─ 标签页栏（main / 编辑: test / test@main）
   ├─ 芯片面包屑（SQLite_du3h / test / main@main / 3 字段）
   ├─ 上下文工具条（字段筛选 / 表属性 / 数据工具 / 字段编排）
   ├─ 条件条（全部列 ▾ | WHERE ▾ | ORDER BY ▾）
   ├─ 操作条（编辑结构/主键建/刷新/自动/跳转到/新增行/删除行/预览SQL/提交/回滚）
   ├─ 数据网格（列头带类型 + 排序箭头 + 列操作小三角）
   ├─ SQL 预览区（可执行标记 / 复制 SQL / 语句计数）
   └─ 状态栏（行数·耗时·待保存项数 | 当前 SQL | SUM/AVG·每页行数·分页·导出）
```

我们的现状：`顶栏菜单 → 左侧对象树 → 右侧 上下 Paned（上=页签区，下=SQL 编辑器）`
—— **面包屑、条件条、状态栏信息量、主按钮层级** 这四块是最大的空洞。

## 二、阶段清单（按依赖与性价比排序）

### 阶段 43：芯片式面包屑 ⭐ 先做

- **对标**：dbx 标签页下那排 `SQLite_du3h / test / main@main / 3 字段` 小圆角标签。
- **现状**：我们**完全没有**——打开一张表，页签标题之外没有任何"我在哪"的提示。
- **改动点**：
  - `panel/dbui.rs`：给 `ResultTab` 加一个 `crumbs: gtk::Box`（页签内容顶部第一行）；
  - 表结构页签 / 定义页签也各加一条（面包屑内容不同）；
  - 芯片用**静态 Label**（不是按钮），加 CSS 类 `.pp-crumb`；
  - 面包屑随选中对象变化：连接名 → 模式 → 表名 → 「N 字段」。
- **样式**：`theme.rs` 加 `.pp-crumb`（小圆角、淡底、`font-size: 0.85em`、左右 padding 6px）。
  ⚠️ **别用 `.pp-chip`**——那个类带着状态色语义（绿/黄/红），用来标"凭据库未启用"。
- **验收**：单测（面包屑文本拼装纯函数）+ 冒烟截图。
- **风险**：低。**注意**：新增的 widget 要挂在 tab 内容里，**不要挂 `PanelState`**（引用环红线）。

### 阶段 44：主操作按钮突出 ⭐ 先做

- **对标**：dbx 的「新增字段」「应用变更」是**黑色实心主按钮**；右侧「提交」也是实心。
- **现状**：阶段 39 把按钮文字全去掉后，**所有按钮权重完全一样**，用户不知道该点哪个。
- **改动点**：
  - `theme.rs` 加 `.pp-primary`（强调底色 + 白字 + hover/active 变体）；
  - 表设计器：工具栏「保存修改」改用 `.pp-primary`；
  - 结果网格：编辑模式下的「保存修改」改用 `.pp-primary`；
  - 表设计器右下角加**常驻「应用变更」主按钮**（dbx 位置），与工具栏的保存按钮**联动**。
- **验收**：冒烟断言主按钮带 `.pp-primary` 类 + 截图。
- **风险**：低。⚠️ GTK4 里 `button.flat` 优先级高于自定义类，别给主按钮加 `flat`。

### 阶段 45：底部状态栏信息量 ⭐ 先做

- **对标**：dbx 底部那一长条：`共 N 行 (统计总行数) | 1ms | 1 项待保存 | SELECT … | SUM: 0 AVG: -- | 100 行/页 | ‹ 1 › | 导出`。
- **现状**：我们只有**一行 Label**（"就绪" / "查询完成：4 行 · 79"）。
- **改动点**：
  - `panel/dbui.rs`：`ui.status`（单 Label）→ 拆成 `gtk::Box` + 若干 Label：
    左：行数 / 耗时 / 待保存项数；中：当前 SQL；右：选中统计 / 每页行数 / 分页控件 / 导出。
  - 分页控件：首页 / 上一页 / 页码 / 下一页 / 末页（**每页行数可调**：100 / 200 / 500 / 1000）。
  - 「统计总行数」：PG 游标拿不到总数 → **异步发一条 `COUNT(*)`**（大表很贵，放后台、不阻塞网格）；
    MySQL 走 `information_schema.TABLES.TABLE_ROWS` 估算。**标题要写明是估算**。
- **验收**：单测（状态栏文本拼装）+ e2e 断言行数 / 待保存数。
- **风险**：中。分页控件要接 `next_page`（PG 游标 / MySQL 客户端切片，**前翻不了**——
  MySQL 目前只能往后翻，翻页控件里"上一页"对 MySQL 要禁用并写明原因）。

### 阶段 46：网格多选 + 列头增强

- **对标**：dbx 列头是 `a` + 小字 `TEXT` + 排序箭头 + 右侧小三角（列操作菜单）+ 列宽拖拽柄。
- **现状**：列头**只有列名**；网格**单选**（没设 `SelectionMode::Multiple`）。
- **改动点**：
  - `panel/dbgrid.rs`：`rebuild_columns` 用 `set_title_widget` 换成「列名 + 类型小字」的 Box；
  - 列头右侧小三角 → 列操作菜单（该列升/降序、复制列名、隐藏此列、设为筛选列）；
  - 网格改多选（`SelectionMode::Multiple`）—— **批量操作的前置**。
- **验收**：冒烟断言列头 widget 含类型 Label + 多选可用。
- **风险**：中。⚠️ **改多选要确认现有单击逻辑**（编辑单元格、删除行）不依赖单选。
- **✅ 已完成（2026-10-29）**：
  - **列头**：`TreeViewColumn::set_widget()` 换成「列名 + 类型小字 + ⋮」的 Box
    （⚠️ 2026-10-29 实测更正：`set_widget` **只换列头、不动列内容**，见 AGENTS.md；
    但 **`set_title()` 必须留着**——导出 / 过滤条件编辑器 / 列类型映射都靠
    `col.title()` 拿列名，少写一句那里全是空串）。
  - **列操作菜单**：点「⋮」或**右键列头**都能弹。条目：升序 / 降序 / 复制列名 /
    复制这一列的数据 / 隐藏这一列（落盘走 `columns.ini`）/ 类型（兜底显示）。
  - **多选**：结果网格 `SelectionMode::Multiple`；**表结构页签的字段表保持单选**
    （一次删一个字段，删字段要一条条生成 ALTER）。
  - **「删除行」删全部选中行**（dbx 语义）：`RowAction::Delete(Vec<usize>)`，
    **倒着删**（删一行会让后面的显示行号往前挪）。
  - ⚠️ **点「⋮」不能顺带排序**：GTK4 里点子控件仍会冒泡到列头按钮
    → 用 `tri_pressed` 标志把那次排序吃掉（已用 xdotool 真点击验证）。
  - **验证**：`examples/grid_header_smoke.rs`（新，不连库）——列头结构 / 类型小字 /
    多选 / **真点击 ⋮**（xdotool）弹菜单且不排序；`db_ui_smoke` 加了同类断言；
    PG e2e 加了 3.11 段（多选两行 → 点**真实**「删除行」按钮 → 两行都被标记删除）。
  - **没做**：**设为筛选列**（过滤条件编辑器已能选列，重复了）。
  - ✅ **「列宽拖拽柄」已补（阶段 85，2026-11-14）**：
    - ⚠️ **原先那条判断是错的**：写着「GTK4 无内置，得自实现 GestureDrag +
      fixed_width，收益低、风险高」。**GTK 自己就能拖列宽**——`set_resizable(true)`
      之后抓住列按钮的**外边缘**就能拖（GTK 源码 `gtk_tree_view_column_set_resizable`
      的说明写得很清楚；"Deprecated: 4.10" 指的是 **TreeView / TreeViewColumn
      整个过时**（该换 `GtkColumnView`），**不是**"不能拖了"）。
      2026-11-14 实测：把它设成 `false` 就真的拖不动了 ⇒ **差点白写一整套手势**。
    - **真正缺的不是"能不能拖"，而是"拖了之后别被冲掉"**：`apply_column_widths`
      每次都按"可用宽度"重排所有列 ⇒ 不记住用户拖出来的宽度，拖完一松手、面板
      一窄就没了（用户看到的就是"拖不动"）。
    - **怎么记住**：⚠️ **看 `fixed_width` 而不是 `width`**——
      `width` 是 GTK **实际分配**的宽度（要等布局跑完才准）⇒ 拿它跟"打算给的"
      比会把**每一列**都误判成"用户拖过"（实测四列全被钉死 ⇒ 自动分配废了）；
      `fixed_width` 是**我们自己设的值**，一设就准，而 GTK 在**用户拖拽**时
      **也会改它**（`gtk_tree_view_column_drag_gesture_update` 里
      `gtk_tree_view_column_set_fixed_width (column, new_width)`）⇒ 一比就知道。
    - **宽度分配**：新增 `alloc_widths_with_fixed()`（纯函数）——钉死的列原样保留，
      其余列按自然宽的比例分剩下的空间；钉死的加起来超过可用宽 ⇒ 其余列拿
      `MIN_COL`，多出来的让横向滚动条出场（用户拖宽一列就该看到滚动条）。
    - **恢复**：列菜单里加「恢复默认宽度」（**只有拖过才出现**）；换结果集时
      清掉用户宽度（按原始下标套到新列上会错位）。
    - **顺带修一个真 bug**：列头**右键**菜单用的是**显示位置**，而菜单里的操作
      全按**原始列下标**走 ⇒ 藏过列之后右键第 2 列会作用到别的列上。
    - ⚠️ **还没做（可以后补）**：用户拖出来的列宽**没有落盘**（重开页签就回到
      自动分配）——列的**顺序与可见性**是存在 `columns.ini` 的（按连接 + 表分区），
      宽度要不要跟着存，看用户反馈。
    - **验证**：单测 5 条（`alloc_widths_with_fixed`）+ `examples/grid_colwidth_smoke.rs`
      （新，不连库）：**xdotool 真拖**列头边缘 ⇒ 列宽真的变了**且被记住**；
      拖过的列不被重排覆盖；**单击列头照常排序**（拖拽手势没把单击抢走）；
      「恢复默认宽度」有效；藏列后列菜单作用到正确的列。⚠️ **两组反向验证**
      （不记用户宽度 / 列菜单退回用显示位置 ⇒ 冒烟当场红）。

### 阶段 47：网格右键菜单补齐

- **对标**：dbx 右键 20+ 项。
- **现状**：只有导出/编辑/插入/删除等基础项。
- **改动点**（`panel/dbgrid.rs` + `dbui.rs`）：
  - 行内编辑类：设为 NULL / 批量修改所选（多选前提）/ 生成值（序列·UUID·当前时间，按方言）/ 克隆为新行；
  - 查看类：单元格详情 / 列详情 / 行详情（**独立窗口**，跟"对象属性"一致）；
  - 视图类：转置查看（行↔列互换，本地算）；
  - 其它：清除选区 / 截图选中区域（cairo 渲染成 PNG）。
- **验收**：单测（转置、批量修改的纯函数）+ 冒烟（菜单项存在且点得动）。
- **风险**：中高。"生成值"要按方言分派（PG `nextval` / MySQL `AUTO_INCREMENT`）。
- **✅ 已完成（2026-10-29）**：
  - **结果网格右键菜单**（dbx 的 20+ 项里挑最有用的 9 项）：
    设为 NULL / 批量修改所选… / 克隆为新行 / 单元格详情… / 行详情… /
    列详情… / 转置查看… / 复制单元格 / 复制整行。
  - **右键未选中的行 → 只选它**；右键已选中的行 → **保留多选**
    （Navicat / dbx 的行为：不然"框选 5 行再右键"就白框了）。
  - **「设为 NULL」零成本**：`edit_literal` 本来就认 `"null"` 文本
    （生成 SQL 的 NULL，不是字符串 `'NULL'`）。
  - **详情窗口**：独立窗口 + 「属性 | 值」两列（跟「对象属性」一个路数）。
    单元格详情 = 列名 / 类型 / 当前值 / 原始值 / 主键；
    列详情 = 列名 / 类型 / 主键 / 行数 / NULL 数 / 不同值个数 / 样例值。
  - **转置查看**：纯函数 `transpose()`（行列互换，类型退化成文本、主键清空）
    + 单测；开独立窗口显示。
  - ⚠️ **顺手修了一个真 bug**：`rebuild_rows` 重建 model 会**丢选中行**
    （`store.clear()` 把选择清了）——改完一个格子就"失选"，用户没法接着
    改第二行。现在重建前记住选中的 `RowRef`、重建后选回去。
  - **验证**：440 单测（+1 转置）+ compat 80 + `grid_header_smoke`
    （**xdotool 真右键**弹菜单、点「设为 NULL」「克隆为新行」都生效）+
    `db_ui_smoke` **离线**（灌假数据）验详情 / 转置 / 批量修改。
  - **没做**：**截图选中区域**（cairo 渲染）、**清除选区**。
  - ✅ **「生成值」已补（阶段 85，2026-11-14）**：
    - **入口**：结果网格**行右键菜单**里加一项「生成值…」（灰着 = 不在编辑
      模式，或右键点在行号那一侧没有具体列）。
    - **五种**：序列 / 自增、UUID、当前时间、当前日期、随机数（对话框里的
      下拉 + 实时预览「将写入：=xxx」）。
    - ⚠️ **按方言分派**（`dbmeta::GenValue::expr`）：UUID = PG
      `gen_random_uuid()` / MySQL `UUID()`；随机数 = PG `random()` / MySQL
      `RAND()`；当前时间 / 当前日期两家通用；**序列 / 自增两家都用
      `DEFAULT`**（= 列的默认值：PG 的 `serial`/`identity`、MySQL 的
      `AUTO_INCREMENT` 都走这条 ⇒ 不用知道序列叫什么名字）。
    - ⚠️ **值由数据库算，不在客户端算**：序列必须由数据库分配（客户端自己数
      会撞号）；「当前时间」要用**数据库的时钟**（客户端时钟可能跟库差几分钟、
      时区也可能不同 ⇒ 写进去的时间对不上，比没写还糟）。
    - ⚠️ **实现要点**：写进格子的是一条**表达式**（`=CURRENT_TIMESTAMP`），
      `dbmeta::edit_value()` 认 `=` 前缀 ⇒ **原样拼进 SQL**（不加引号）⇒
      库里存的是算出来的值。⚠️ **另起函数而不是改 `edit_literal`**：后者
      还被**导入**（CSV 批量入库）与**导出脚本**共用 ⇒ 那些地方的文本是
      **数据**，绝不能当 SQL 执行。
    - **验证**：单测 5 条（`edit_value` 的 `=` 前缀 / 空表达式报错 / 各方言的
      表达式 / UPDATE 与 INSERT 里原样出现）+ `db_ui_smoke` **离线**跑通
      真实路径（弹菜单 → 点「生成值…」→ 对话框 → 选 UUID → 确定 → 这一格
      变成 `=gen_random_uuid()` ⇒ UPDATE 里是 `SET "name" = gen_random_uuid()`，
      **没有引号**）；⚠️ **反向验证**（`build_updates` 退回 `edit_literal`
      ⇒ 单测与冒烟当场红）。

### 阶段 48：可视化 WHERE / ORDER BY 构造器

- **对标**：dbx 的 `全部列 ▾ | WHERE ▾ | ORDER BY ▾` 条件条。
- **现状**：只有「过滤条件…」弹窗手写 Where，**没有 ORDER BY**，也没有"列 → 条件"的图形化。
- **改动点**：条件条 = 三块（列下拉 / 运算符下拉 / 值输入）+「添加条件」；生成 SQL 片段拼到查询前面。
- **验收**：单测（条件 → SQL 的拼装）+ e2e（带条件查真库）。
- **风险**：高。⚠️ 值要按列类型转义（引号 / NULL / 数字）。
- **✅ 已完成（2026-10-29）**：
  - **条件条**（`panel/dbui.rs::CondBar`）：一行控件 =
    `条件 | 并且/或者 ▾ | 列 ▾ | 运算符 ▾ | 值 | + 条件 | 排序 | 列 ▾ | ↑升序/↓降序 | 清除`，
    下面一行是**已生效条件的 chip**（`列 = 值` + ✕ 移除）。
  - **只在表浏览页签亮出来**：普通查询结果是用户手写的 SQL，往里拼
    WHERE / ORDER BY 是越权。
  - **SQL 侧**：`dbmeta::build_order_by()`（列名按方言加引号）+ 新增
    `build_select_table_page_order()`（**WHERE → ORDER BY → LIMIT/OFFSET**，
    顺序写反直接语法错）；老函数转调新函数，签名不变。
  - **值按列类型转义**：整数列不加引号（`"id" = 1`）、文本列加引号
    （`"name" = '张三'`）——复用 `build_where` + `edit_literal`。
  - ⚠️ **顺手修了一个真 bug**：`col_type_map` 原先拿「网格的显示位置」
    配 `tab.types`（元数据顺序），**隐藏过列以后就错位**——int 列会被
    当成 text 列，条件里的值多套一层引号（PG 报类型错）。
    现在列名与类型都取自**元数据**（同序配对）。
  - ⚠️ **`ComboBoxText::append(id, text)` 的顺序**：`id` 是程序里认的，
    `text` 是给用户看的。写反了（`append("并且", "AND")`）的话，
    `active_id()` 回来的是"并且"，判断 `"OR"` 永远不成立 →
    **「或者」这个选项形同虚设**（看着能选，选了没反应）。
  - **验证**：444 单测（+4）+ compat 80 + `cond_bar_smoke`（**走真实按钮
    回调**：加条件 / 「或者」/ 排序 / 切方向 / 清除，断言生成的 SQL）+
    e2e 新增 3.13 段（带条件重查真库 → 行数变少且剩下的行都满足条件）。

### 阶段 84：dbx 观感复查后的三件改造（D1 / D2 / D3）

> 2026-11-12：用户说「不光是筛选，我们可以多拿一些它的优点」⇒ **实际打开 dbx
> 点了一遍按钮并截图对比**（工具条 / 底栏 / 列头菜单 / 网格右键 / 表属性抽屉 /
> 预览 SQL 抽屉 / 新建查询编辑器），再对着自己这边（aly 真库）拍图比差距。

- **D1 常驻 WHERE 框**（替代「🔽 过滤条件」弹窗 + 条件 chip 行）：
  一个宽输入框 + **回车即检索**（自由文本）；结构化挑条件收进 ▾ **条件助手**
  （按列类型转义，生成一段一定能跑的条件）；「填入」**不自动查库**。
  ⚠️ **WHERE 的唯一真相是自由文本**（`filter_where`），结构化条件只是生成文本
  的中间产物；⚠️ 只拦引号外的分号（一条查询一条语句）。
- **D2 条件条并进工具条一行 + 底栏三段式**：条件条以前独占一行 + chip 再占
  一行 ⇒ 网格被挤掉一大截 ⇒ 并进工具条（网格多出整整两行）；页签「状态」从
  工具条搬到底栏；底栏 = 左（行数·耗时·待保存）+ 中（**当前 SQL 常驻**）+
  右（**「统计总行数」** + 每页行数 + 分页）。
  ⚠️ **「总行数」= COUNT(\*)，是真值**；对象树「详细模式」里那个是**估算值**
  （≈），两者界面上要分清；⚠️ **只有表浏览页签能数**（手写查询不知道表名）。
- **D3 属性页加「查看 DDL」**：属性页下面多一段 **CREATE TABLE 文本**（只读 +
  可复制 + SQL 高亮）；⚠️ **视图不假装有**（视图定义要问数据库自己，我们没这
  条通路 ⇒ 只显示一句说明）。

## 三、已知的技术前提（别重复踩）

| 前提 | 含义 |
|---|---|
| PG 用**服务端游标**分页 | `next_page` 只能往后翻；**拿不到总行数**（要总数得另发 COUNT） |
| MySQL 客户端切片 | 上限 2000 行（`MYSQL_BUFFER_LIMIT`），翻页是内存切片 |
| 网格当前**单选** | 批量操作前必须先改多选（阶段 46） |
| 编辑态的改动记在 `edits/inserts/deletes` | 任何"改值"类新功能都要写进这三处，**否则保存时丢改动** |
| 网格列头没有类型信息 | 列类型在 `tab.types` 里，要传到 `DbGrid` 才能显示 |
| 引用环红线 | 挂在 `PanelState` 上的回调一律抓**弱引用** |
| 引用环红线（新增行内按钮） | 字段表里的行内按钮回调 → 抓 `Weak`，否则字段表永远释放不掉 |
